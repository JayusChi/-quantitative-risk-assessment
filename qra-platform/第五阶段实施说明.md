# 第五阶段实施说明：人工复核、质量门禁与不可变快照

## 1. 文档定位

本文是《第一部分项目计划书》的第五阶段可执行开发规格。第五阶段将第四阶段的候选事实、证据、冲突和质量问题提供给业务人员复核，形成唯一、可审计的拟采用数据，并在通过质量门禁后创建不可变 QRA 输入快照。

人工复核不是直接编辑候选或原文。所有操作必须形成独立复核决定，保留修改前后值、证据、人员、时间和原因。

## 2. 阶段目标与出口

业务人员无需查看代码即可：查看任务和问题；打开原文件证据位置；比较同一字段的全部来源；确认、替换、驳回、标记不适用或请求重提取；查看对第二部分计算节点的影响；在无阻断问题后生成不可变快照。

阶段出口：所有关键字段均可追溯；阻断冲突、必填缺失和错误不能提交；复核并发不会互相覆盖；相同确认内容产生相同快照内容哈希；已确认快照不能原地修改。

## 3. 当前基线与复用要求

必须复用：

- `src/qra_converter/contracts.py` 中 `ReviewItem`、`ReviewAuditEntry` 和 `ConversionResult`；
- `src/qra_converter/review.py` 的稳定复核 ID、来源候选和过期决定校验；
- `src/db_qra/database.py` 的 `conversion_job`、`input_snapshot`、`input_snapshot_provenance` 和 `audit_event`；
- `QraDatabase.confirm_conversion()` 的同事务确认和快照创建语义；
- `db_qra.engine_adapter.preview_case()` 的导入合同和动态节点能力预检；
- 管理页面已有任务列表、问题摘要、重试和确认入口；
- 规范化 JSON 和 SHA-256 逻辑。

现有页面通过粘贴 `review_decisions` JSON 重试，只能作为兼容/调试入口。阶段完成后，业务复核必须使用结构化工作台和 API，不能要求用户手写 JSON。

## 4. 范围边界

本阶段包括：

- 复核队列、证据查看、冲突比较和字段编辑；
- 单项和受控批量复核、重提取请求；
- 完整性、合法性、跨字段和第二部分节点门禁；
- 快照组装、规范化、哈希、来源清单和不可变持久化；
- 乐观锁、权限边界和全过程审计；
- 修订形成新任务/新快照。

本阶段不包括：

- 修改原始文件、解析原文或候选事实；
- 由人工把缺失值静默设为 0；
- 自动批准参数库、模型或正式报告；
- 修改已确认快照；
- 在质量门禁未通过时用“强制提交”绕过错误。

## 5. 角色与权限

测试版至少区分逻辑角色，即使首版认证仍由部署层提供：

- `VIEWER`：查看任务、候选、证据和快照；
- `REVIEWER`：作复核决定和备注，不能确认自己无权审批的参数；
- `APPROVER`：执行最终门禁确认和创建快照；
- `ADMIN`：任务管理和配置查看，不能修改审计历史。

高敏感文件证据接口在返回前检查任务权限。操作者不能只信任请求体中的 `actor/reviewer`；部署有认证时从认证上下文获取。当前本地测试兼容值必须显式标记 `LOCAL_TEST_IDENTITY`，生产验证前替换。

## 6. 数据模型与数据库变更

### 6.1 复核会话

新增 `review_session`：

| 字段 | 说明 |
| --- | --- |
| `id` | 会话 ID |
| `conversion_job_id` | 所属转换任务 |
| `candidate_set_sha256` | 会话基于的候选集合哈希 |
| `status` | `OPEN`、`READY_FOR_GATE`、`CLOSED`、`STALE` |
| `revision` | 乐观锁版本 |
| `created_by/created_at` | 创建信息 |
| `updated_at` | 最近修改时间 |

一个候选集合只能有一个活动会话。第四阶段重新提取并改变候选集合后，旧会话置 `STALE`；旧决定保留审计但不得自动应用。

### 6.2 复核决定

新增 `review_decision`：

- `decision_id`、`review_session_id`、`review_item_id`；
- `action`；
- `field_id`、`entity_key`、`target_path`；
- `candidate_set_sha256`、`selected_candidate_ids_json`；
- `before_value_json`、`after_value_json`；
- `reason`、`reviewer`、`reviewed_at`；
- `evidence_ids_json`；
- `supersedes_decision_id`；
- `decision_sha256`。

决定不可 UPDATE/DELETE。修改决定时插入新记录并通过 `supersedes_decision_id` 形成链，当前视图取最新有效决定。

### 6.3 门禁运行

新增 `quality_gate_run`：

- 候选集合哈希、决定集合哈希、合同/字段/规则版本；
- 组装草稿哈希；
- Schema 校验、引擎导入校验和动态能力计划摘要；
- `status`：`PASS`、`PASS_WITH_WARNING`、`BLOCK`；
- 问题数量、阻断原因和时间。

确认只能引用当前候选集合和当前决定集合上的最新 `PASS` 或允许策略下的 `PASS_WITH_WARNING`。任何新决定都会使旧门禁运行失效。

### 6.4 快照清单

扩展 `input_snapshot_provenance` 或增加快照清单，至少固化：

- 输入内容 SHA-256；
- 源文件清单及每个 SHA-256；
- 解析器、OCR、模型、提示词、字段字典、单位、融合、质量规则版本；
- 候选集合哈希、复核决定集合哈希、门禁运行 ID；
- 复核人、批准人和时间；
- 数据分类和测试/正式标记；
- 从该快照可追溯的证据索引哈希。

## 7. 复核项分类和优先级

工作台至少提供：

- `BLOCKING_CONFLICT`：关键冲突；
- `REQUIRED_MISSING`：合同或目标节点必需字段缺失；
- `INVALID_VALUE`：类型、单位、范围或逻辑错误；
- `LOW_CONFIDENCE`：低置信度关键字段；
- `IDENTITY_AMBIGUOUS`：对象归属不唯一；
- `WARNING`：可提交但需要知情确认；
- `UNREVIEWED_CHANGE`：候选或规则变化使旧决定失效。

默认排序：阻断程度 → 影响的计算节点数量 → 字段敏感级别 → 置信度升序 → 实体/桩号。用户可按资料、字段组、管段、状态和问题码筛选。

## 8. 工作台页面结构

### 8.1 页面布局

```text
┌────────任务与门禁摘要────────┐
│ 进度 / 阻断数 / 警告数 / 可运行节点 │
├────问题列表────┬────字段复核区────┬────证据查看区────┤
│ 筛选、分组、排序 │ 候选比较、标准值、决定 │ 原页/表格/图片高亮 │
└────────────────────────────────────┘
```

在窄屏下按“列表 → 详情 → 证据”顺序切换，不把三栏强行压缩。

### 8.2 字段复核区

显示：字段中文名和 ID、实体、原值、标准值、单位换算、置信度、资料类型、日期、来源等级、系统建议及理由。冲突候选并排展示，差异数值和单位高亮。

允许动作：

- 采用某候选；
- 采用多个互补候选（仅对合同允许的多值字段）；
- 输入替代值，并强制填写原因和选择/新增人工证据；
- 驳回该字段；
- 标记不适用；
- 请求对指定文件/页面/字段重新提取。

人工替代值必须经过与机器候选相同的类型、单位和范围校验，不能以字符串绕过。

### 8.3 证据查看区

- 表格证据显示工作表、行列和邻近上下文，高亮原单元格；
- PDF/图片显示受控预览，按 bbox 高亮；
- DOCX 显示段落/表格结构位置；没有页码时显示“段落 N / 表格 N”，不伪造页码；
- 可在同一冲突项中切换全部来源；
- 证据预览请求按源 ID 和资源 ID，禁止任意路径；
- 预览内容使用正确 `Content-Type`、`Content-Disposition` 和禁止脚本执行的安全响应头。

## 9. 前端代码治理

现有 `admin_ui.py` 是内嵌 HTML/CSS/JS。复核工作台加入后文件会过大，本阶段先做不改变行为的静态资源拆分：

```text
src/db_qra/web/
├─ index.html
├─ styles.css
├─ app.js
├─ conversions.js
└─ review.js
```

在 `pyproject.toml` 将静态资源加入包数据，`server.py` 只提供受控固定资源路由。不得引入构建链或前端框架作为阶段前置条件；测试版使用原生 HTML/CSS/JavaScript 即可。

所有用户内容通过 `textContent` 或统一 `esc()` 处理。证据文本、文件名、原因和模型输出不得直接写入 `innerHTML`。

## 10. 复核 API

### 10.1 会话和列表

- `POST /admin/api/conversions/{job_id}/review-sessions`：创建或返回当前会话；
- `GET /admin/api/review-sessions/{session_id}`：摘要、revision 和门禁状态；
- `GET /admin/api/review-sessions/{session_id}/items?kind=&status=&field_id=&entity=&cursor=`；
- `GET /admin/api/review-sessions/{session_id}/items/{review_item_id}`：候选、问题、建议和证据摘要。

### 10.2 证据

- `GET /admin/api/evidence/{evidence_id}`：证据元数据与上下文；
- `GET /admin/api/evidence/{evidence_id}/preview`：受控页面/图片/表格预览；
- `GET /admin/api/evidence/{evidence_id}/crop`：可选局部图，服务端按登记 bbox 生成，不接受任意裁剪路径。

### 10.3 决定

- `POST /admin/api/review-sessions/{session_id}/decisions`；
- `POST /admin/api/review-sessions/{session_id}/decisions/bulk`；
- 请求必须带 `expected_revision`；
- revision 不一致返回 HTTP 409 和最新摘要；
- 成功后插入不可变决定、revision 加 1、旧门禁失效并记录审计。

批量确认只允许同类、同规则且没有冲突的非关键项。冲突、人工替代值、批准参数和低置信度关键字段禁止一键批量接受。

### 10.4 重提取和门禁

- `POST /admin/api/review-sessions/{session_id}/reextract`：指定源/页/字段，创建第四阶段子任务；
- `POST /admin/api/review-sessions/{session_id}/gate-runs`：组装草稿并运行门禁；
- `POST /admin/api/review-sessions/{session_id}/confirm`：引用最新门禁运行创建快照；
- 现有 `/conversions/{id}/confirm` 保留兼容，但内部必须转到同一应用服务，不能绕过新门禁。

## 11. 质量门禁

门禁顺序固定：

1. 候选集合哈希和会话有效性；
2. 所有阻断复核项已决定；
3. 复核决定未过期、动作合法、操作者权限满足；
4. 按决定组装唯一拟采用数据；
5. 第一阶段 JSON Schema；
6. 必填、类型、单位、范围和枚举；
7. 概率归一化、管段连续性、压力关系、对象归属和跨字段逻辑；
8. `qra_engine.validation.validate_import_contract`；
9. `plan_dynamic_flow` 计算可运行/阻断节点；
10. 项目所选“目标计算节点”均可运行；
11. 参数批准、数据分类和正式报告门禁；
12. 生成门禁报告和草稿哈希。

“动态节点有缺失”不一定阻断部分数据快照。任务创建或复核会话必须声明 `target_node_ids`：

- 至少要求 `segment_geometry` 和测试版风险筛查节点时，只阻断这些目标；
- 用户选择完整人员 QRA 时，`human_qra` 的全部缺口阻断；
- 未经批准的频率库或测试参数允许测试计算，但快照明确 `TEST_EDITION`，`formal_report_allowed=false`。

未声明目标时使用项目默认目标集，不允许系统把所有当前能运行的节点当作用户已同意的范围。

## 12. 快照组装与不可变性

### 12.1 组装规则

- 仅采用当前有效复核决定指向的候选或人工值；
- 未决候选、模型原始响应和复核 UI 状态不得进入计算输入；
- 系统派生字段记录规则和输入候选；
- 缺失保持缺失，不补零；
- 数组按稳定业务键排序，JSON 对象键规范化；
- 禁止 `NaN/Infinity`；
- 内容 JSON 与来源清单分别规范化并各自计算哈希。

### 12.2 内容寻址

相同规范化输入内容复用同一 `input_snapshot`，但每次确认可产生独立 provenance/审计关系。快照 ID 可以是 UUID，`payload_sha256` 才是内容身份。

快照创建和转换任务确认必须在一个数据库事务内完成：

1. 再次检查 revision 和门禁哈希；
2. 插入或复用快照；
3. 插入来源、候选、复核和门禁 provenance；
4. 更新任务/会话状态；
5. 写审计事件；
6. 任一步失败全部回滚。

已被计算任务引用的快照不可删除。未使用快照的删除应为受审计的管理动作，并按现有数据库规则执行；不得级联删除原始审计。

## 13. 并发与防误操作

- 决定写入使用 `expected_revision` 乐观锁；
- 页面检测到 409 时刷新当前项并提示其他复核人的变化；
- 用户离开有未提交编辑的页面时提示；
- 最终确认前展示快照名称、目标节点、阻断数、警告数、数据分类、参数状态和内容哈希前缀；
- 确认操作需要明确原因，不能用浏览器 `prompt/confirm` 作为最终界面；
- 双击或网络重试使用幂等键，不能创建不同内容的重复确认；
- 批量操作先返回影响预览，再由用户提交。

## 14. 审计事件

至少新增：

- `REVIEW_SESSION_OPENED`；
- `REVIEW_DECISION_CREATED`；
- `REVIEW_DECISION_SUPERSEDED`；
- `REVIEW_BULK_APPLIED`；
- `REEXTRACTION_REQUESTED`；
- `REVIEW_SESSION_STALE`；
- `QUALITY_GATE_STARTED/PASSED/BLOCKED`；
- `SNAPSHOT_CONFIRMED_FROM_REVIEW`。

审计详情保存 ID、哈希、动作和原因，不复制大段原文或敏感文件内容。审计时间统一 UTC ISO 8601，页面按用户时区显示。

10. 事务任一步失败不留下半确认状态。

集成/E2E 至少覆盖：

- 打开冲突任务、比较两份资料证据、选择候选并通过门禁；
- 人工替代值要求原因和证据；
- 缺失关键字段阻断完整 QRA，但可按批准范围形成测试筛查快照；
- 两个复核人并发修改返回 409，不覆盖决定；
- 重提取使旧会话过期；
- 快照详情可追溯到源文件、候选、决定和版本；
- 已确认快照不能编辑；修订产生新任务和新快照；
- 页面不执行证据中的 HTML/脚本文本。

最后执行 `scripts/test.ps1` 全量回归。

## 18. 向第六阶段移交

移交不可变输入快照、快照 provenance、门禁报告、目标节点、数据分类、正式报告允许状态和内容哈希。第六阶段不得重新读取候选表或复核草稿来计算，也不得在适配器中修改快照内容。
