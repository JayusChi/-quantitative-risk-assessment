# 第二阶段实施说明：文件接收与资料任务管理

## 1. 文档定位

本文是《第一部分项目计划书》的第二阶段可执行开发规格。目标是在现有 `db_qra` 转换任务和管理页面上，形成安全、稳定、可追溯的资料入口。上传成功只表示资料已登记，不表示资料内容正确，也不表示可以进入第二部分计算。

## 2. 阶段目标与出口

用户能够创建资料处理任务，上传单文件、多文件或 ZIP 资料包，查看文件清单、指纹、分类和任务状态。系统必须阻止不支持、损坏、伪装或不安全的文件进入解析队列，并保留所有接收和状态变化审计记录。

阶段出口：约定格式的模拟资料包可稳定登记；重复和版本关系可见；ZIP 无路径穿越和压缩炸弹风险；服务重启后未完成任务可恢复；异常文件不会被第三阶段解析器处理。

## 3. 当前基线与必须复用能力

现有能力位于：

- `src/db_qra/conversion_adapter.py`：文件名检查、扩展名白名单、大小/数量限制、SHA-256、ZIP 路径检查、任务提交和后台执行；
- `src/db_qra/database.py`：`conversion_job`、`conversion_source`、审计事件和状态持久化；
- `src/db_qra/server.py`：转换任务 API、批量提交、重试、确认和后台线程；
- `src/db_qra/admin_ui.py`：源资料选择、Base64 上传、进度状态和任务列表；
- `tests/integration/test_converter_phase3.py`、`test_database_end_to_end.py`：现有转换/API 回归。

当前白名单为 CSV、XLS、XLSX、DOCX、PDF 和 ZIP；本阶段补齐 PNG、JPG/JPEG。现有 18 MB 限制属于测试版默认值，可以配置，但不能直接删除安全上限。

## 4. 范围边界

本阶段包括：

- 创建任务、上传进度、文件登记、取消和失败重试；
- 扩展名、文件签名、MIME、完整性和容器结构检查；
- ZIP 安全展开、相对目录保留和成员登记；
- SHA-256 去重、同名异版和版本组识别；
- 原始文件受保护存储、任务状态机和审计；
- 文件的粗粒度技术分类，不做业务字段抽取。

本阶段不包括：

- 文档正文解析、OCR、大模型资料主题分类；
- 自动判断哪个冲突值正确；
- 把文件直接写成计算快照；
- 可恢复分片上传。测试版使用单请求上传，浏览器显示传输进度；大文件/断点续传作为后续扩展。

## 5. 状态模型

### 5.1 任务状态

沿用并明确现有状态：

```text
QUEUED → RUNNING → READY_FOR_CONFIRMATION → CONFIRMED
             ├──→ BLOCKED → RETRY(新任务)
             ├──→ FAILED  → RETRY(新任务)
             └──→ CANCELLED
```

- `QUEUED`：文件全部登记并通过入口检查，等待处理；
- `RUNNING`：第三、四阶段流水线正在处理；
- `BLOCKED`：文件可读，但质量或人工复核门禁阻断；
- `FAILED`：执行器异常；
- `READY_FOR_CONFIRMATION`：内容处理完成且无阻断项；
- `CONFIRMED`：已生成或复用不可变快照；
- `CANCELLED`：用户取消且未确认；取消不删除审计和文件指纹。

任务重试必须创建带 `parent_job_id` 的新任务，不得清空或重写原任务结果。`CONFIRMED` 不允许取消或重试，只能基于原资料创建新任务。

### 5.2 文件状态

每个源文件独立记录：

- `RECEIVED`：已收到原始字节；
- `VALIDATED`：入口安全检查通过；
- `QUARANTINED`：类型、签名、结构或安全检查失败；
- `DUPLICATE`：同任务或历史任务存在相同内容；
- `READY_FOR_PARSE`：允许第三阶段读取；
- `PARSE_FAILED`、`PARSED`：供下一阶段更新。

任务只有在至少一个文件 `READY_FOR_PARSE` 且没有阻断型隔离文件时才能排队。是否允许“隔离坏文件、继续处理好文件”由任务选项 `failure_policy` 决定，测试版默认 `ALL_OR_NOTHING`。

## 6. 数据库变更

通过显式迁移把数据库 `SCHEMA_VERSION` 升级，不依赖删除重建。为 `conversion_job` 增加：

| 字段 | 用途 |
| --- | --- |
| `contract_id/version/sha256` | 固化第一阶段合同 |
| `failure_policy` | `ALL_OR_NOTHING` 或批准后的 `QUARANTINE_AND_CONTINUE` |
| `cancel_requested_at` | 协作式取消标记 |
| `cancelled_at/cancelled_by` | 取消审计 |
| `file_manifest_sha256` | 排序后的文件清单哈希 |
| `revision` | 后续复核乐观锁版本，初始为 1 |

为 `conversion_source` 增加或确认：

| 字段 | 用途 |
| --- | --- |
| `relative_path` | ZIP 内相对路径或顶层安全文件名 |
| `original_file_name` | 用户看到的名称 |
| `declared_media_type` | 浏览器声明 MIME，仅作参考 |
| `detected_media_type` | 系统按签名/容器判断的类型 |
| `byte_count/sha256` | 完整性和去重 |
| `source_kind` | `TABULAR`、`NATIVE_DOCUMENT`、`PDF`、`IMAGE`、`UNKNOWN` |
| `security_status` | 文件状态和隔离原因 |
| `duplicate_of_source_id` | 完全重复来源 |
| `version_group_id` | 同名异哈希或显式版本关系 |
| `archive_name/archive_member_path` | ZIP 来源关系 |
| `created_at` | 登记时间 |

原始字节可以沿用数据库 BLOB 存储，但管理页只读数据库视图不得返回内容列。若改为文件对象存储，数据库保存受控对象键和哈希，路径解析只能位于 `QRA_WORKSPACE_ROOT`，不能接受用户提供的绝对路径。

## 7. 文件类型与签名检查

新增 `src/db_qra/file_intake.py`，把入口检查从 `conversion_adapter.py` 拆出。检查顺序固定为：

1. 文件名规范化和控制字符检查；
2. 扩展名白名单；
3. 单文件、文件数和任务总量限制；
4. SHA-256 和字节数；
5. 文件签名/容器结构；
6. 声明 MIME、扩展名与检测类型一致性；
7. ZIP 安全检查；
8. 去重和版本关系；
9. 生成不可变文件清单哈希。

首版签名规则：

- PDF：以 `%PDF-` 开头且可由 PDF 读取库打开；
- PNG：标准 8 字节签名；
- JPG/JPEG：SOI/EOI 标记且图像库能读取尺寸；
- XLSX/DOCX：ZIP 容器，必须分别包含约定 OOXML 部件；
- XLS：OLE Compound File 签名；
- CSV：无可靠魔数，必须通过文本编码、NUL 字节、控制字符比例和 CSV 可解析性检查；
- ZIP：标准容器且不是伪装的 XLSX/DOCX。

扩展名和签名不一致产生 `INTAKE.TYPE_MISMATCH` 并隔离。不得仅信任浏览器 `Content-Type`。

## 8. ZIP 安全规则

复用 `_safe_archive_member` 并补齐以下限制：

- 禁止绝对路径、盘符、UNC、`..`、空路径、符号链接和加密成员；
- 路径统一按 POSIX 处理后再映射到任务临时目录；
- 限制成员总数、单成员大小、总展开大小、目录深度和文件名长度；
- 增加压缩比阈值，防止小压缩包展开为超大数据；
- 禁止嵌套压缩包或将其作为普通未知文件隔离，测试版不递归解压；
- 对重复相对路径按大小写不敏感检查；
- 只展开支持格式，其他成员登记为 `UNSUPPORTED_MEMBER`，是否阻断由策略决定；
- 展开后的每个成员单独计算哈希并进入 `conversion_source`；
- 所有目标路径解析后必须 `is_relative_to` 当前任务临时目录。

不得使用原文件名拼接 shell 命令，不执行宏、脚本或嵌入对象。

## 9. 去重与版本识别

### 9.1 完全重复

同一任务内 SHA-256 相同的文件只保留一个待解析实体，其他来源记录 `duplicate_of_source_id`。不同相对路径仍保留在清单中，以便说明资料包结构。

跨任务遇到相同哈希时可复用安全检查结果，但新任务仍保存独立来源关系和上传审计。不得因为历史任务已解析就绕过当前合同、映射或模型版本。

### 9.2 同名异版

标准化相对路径或文件基本名相同、哈希不同的资料归入同一 `version_group_id`，标记 `POSSIBLE_NEW_VERSION`。文件名中 `v1/v2`、日期、修订号只作提示，不能据此删除旧文件或决定事实优先级。

任务级去重键继续由“有序文件名+文件哈希+映射哈希”计算，并加入合同哈希和入口规则版本。任何影响输出语义的版本变化都必须产生新任务。

## 10. API 规格

保留现有接口并扩展返回字段：

### 10.1 创建任务

`POST /admin/api/conversions`

请求继续包含 `profile`、`project_name`、`case_id`、`actor`、`files`，新增：

```json
{
  "contract": "qra.part1-input/1.0.0",
  "failure_policy": "ALL_OR_NOTHING"
}
```

测试版 `files[*].content_base64` 仍可使用。服务端先限制 HTTP 请求体，再 Base64 解码；Base64 前后的大小都要检查，避免内存放大。

成功返回 HTTP 202；相同任务指纹返回 HTTP 200 和 `deduplicated=true`。错误响应统一包含 `error`、`message`、`issues[]`，不得把服务器绝对路径和异常堆栈返回浏览器。

### 10.2 查询

- `GET /admin/api/conversions?status=&limit=&cursor=`：分页任务列表；
- `GET /admin/api/conversions/{job_id}`：任务、文件清单、状态时间线和问题摘要；
- `GET /admin/api/conversions/{job_id}/sources`：文件元数据列表，不返回原始 BLOB；
- `GET /admin/api/conversions/{job_id}/events`：该任务审计时间线。

### 10.3 取消与重试

- `POST /admin/api/conversions/{job_id}/cancel`：请求协作式取消；
- `POST /admin/api/conversions/{job_id}/retry`：沿用现有接口，创建子任务；
- 后台工作线程在展开前、每文件处理前和外部服务调用前检查取消标记；
- 已进入不可中断库调用时记录“取消待生效”，调用返回后不得继续下一个步骤。

取消接口必须验证当前状态，重复取消应幂等返回当前任务，不得报 500。

## 11. 管理页面要求

在现有“资料自动转换”页面完成：

- 拖放和多选文件；
- 显示每个文件名称、大小、声明类型和本地上传进度；
- 上传前显示格式、数量和总大小限制；
- 能删除误选文件、取消正在发送的 XHR、取消已创建任务；
- 任务详情展示 ZIP 层级、检测类型、哈希前缀、重复/版本标记和隔离原因；
- 状态标签与后端枚举一一对应；
- 错误可操作，如“移除损坏文件后新建任务”，不能只显示“失败”；
- 文件名和服务端文本一律使用转义后的文本节点，禁止拼接未转义 HTML。

浏览器进度只代表上传请求发送比例；任务进度代表服务端处理比例，两者必须用不同文案。

## 12. 原始文件保护与审计

- 原始字节写入后只读，后续解析只读取任务副本或受控临时文件；
- 不能提供任意路径下载接口；如后续需要查看原件，必须通过源 ID、权限检查和固定响应头访问；
- 审计事件至少包括 `CONVERSION_QUEUED`、`SOURCE_RECEIVED`、`SOURCE_QUARANTINED`、`SOURCE_DUPLICATE_FOUND`、`CONVERSION_CANCEL_REQUESTED`、`CONVERSION_CANCELLED`、`CONVERSION_RETRIED`；
- 审计详情不存文件正文、Base64、口令、模型密钥或未脱敏敏感内容；
- 日志记录任务 ID、源 ID 和问题码，不记录 BLOB；
- 临时目录在成功、失败和取消后清理；数据库或对象存储中的受保护原件按保留策略处理。

## 13. 代码任务拆分

### 13.1 任务 A：入口检查组件

1. 新建 `file_intake.py` 和数据类 `DetectedFileType`、`IntakeIssue`；
2. 把大小、文件名、哈希和 ZIP 规则从 `conversion_adapter.py` 移入；
3. 增加 PNG/JPEG 与 OOXML 精确识别；
4. 所有检查返回稳定问题码；
5. `conversion_adapter.py` 只负责组合任务、持久化和调用转换器。

### 13.2 任务 B：数据库迁移与状态机

1. 编写从当前 `SCHEMA_VERSION` 到新版本的增量迁移；
2. 添加文件状态和版本关系字段；
3. 所有状态变化使用带旧状态条件的单事务更新；
4. 实现取消、幂等取消、重试父子关系和重启恢复；
5. 为状态变化记录审计。

### 13.3 任务 C：API 与页面

1. 扩展创建/详情返回；
2. 新增 sources、events 和 cancel 接口；
3. 前端使用 `XMLHttpRequest.upload.onprogress` 显示发送进度和 `abort()` 取消；
4. 页面轮询只在存在活动任务时运行，并采用退避或不低于当前 2 秒间隔；
5. 大列表使用分页，不在任务列表返回 BLOB 和完整解析结果。

### 13.4 任务 D：安全样本

在 `tests/fixtures/intake/` 创建合成文件：正常格式、扩展名伪装、损坏 OOXML、加密 ZIP、路径穿越 ZIP、重复路径、超深目录、高压缩比、空文件、同名异哈希、重复哈希和未知成员。测试夹具不得包含真实项目资料。

## 14. 自动化测试

单元测试至少覆盖：

1. 每种支持格式的签名与 MIME 识别；
2. 扩展名/签名不一致；
3. UTF-8 BOM、GB18030、分隔符异常和含 NUL 的伪 CSV；
4. ZIP 路径穿越、符号链接、加密、成员数、展开量、压缩比、目录深度和大小写重复路径；
5. 同任务去重、跨任务去重和同名异版；
6. 文件清单哈希对输入顺序不敏感；
7. 合同或入口规则版本改变会改变任务去重键；
8. 非法状态转换失败，取消幂等，重试形成父子关系；
9. 取消、异常和服务重启后临时目录清理；
10. API 错误不泄露绝对路径和堆栈。

集成测试至少覆盖：

- 多文件创建任务并查询文件清单；
- ZIP 展开后每个支持成员可追溯到压缩包和成员路径；
- 隔离文件使默认策略任务不进入解析；
- 服务重启后 `QUEUED/RUNNING` 任务按规则恢复；
- 页面含上传进度、取消入口和安全转义；
- 原有转换和数据库端到端测试继续通过。

执行 `scripts/test.ps1` 作为最终回归。

## 16. 向第三阶段移交

第三阶段只接收状态为 `READY_FOR_PARSE` 的源文件，并通过源 ID 读取受控任务副本。移交内容包括文件清单、检测类型、相对路径、哈希、ZIP 来源、任务合同版本和入口问题。解析器不得重新解释上传路径，也不得修改原始文件状态之外的接收事实。
