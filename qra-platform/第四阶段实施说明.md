# 第四阶段实施说明：大模型智能提取、标准化与多来源融合

## 1. 文档定位

本文是《第一部分项目计划书》的第四阶段可执行开发规格。第四阶段把第三阶段的忠实解析结果转换为第一阶段字段字典中的候选事实，再用确定性规则做单位、桩号、日期、枚举和关系校验，最后形成可供第五阶段人工复核的统一候选数据和质量问题。

大模型负责理解和提出候选，不拥有文件系统、数据库、网络或计算提交权限。任何模型输出都必须通过结构化合同、字段白名单和证据绑定校验。

## 2. 阶段目标与出口

对混合模拟资料完成资料分类、对象识别、字段/关系抽取、确定性标准化、多来源匹配、重复识别和冲突检测。每个候选值必须有证据、方法、置信度和版本；无依据或无法唯一解释的内容进入复核，不得编造或静默选择。

阶段出口：黄金资料能形成统一候选字段；预设缺失、重复和冲突被检出；上传资料中的指令性文字不能改变系统任务；模型失败可重试或降级；输出可被第五阶段分页查询和逐项复核。

## 3. 当前基线与复用要求

必须复用：

- 第一阶段合同、字段字典、单位注册表、术语别名和问题码；
- 第三阶段 `ParsedDocument` 和证据 ID；
- `src/qra_converter/mapping/` 的版本化表头映射、类型/单位归一能力；
- `src/qra_converter/matching/chainage.py` 的管段/半开里程关联；
- `src/qra_converter/review.py` 的多来源主键合并、来源优先级、冲突和人工决定合同；
- `src/qra_converter/assembly/`、`validation/`、`reporting/` 的草稿、质量和预览输出；
- `db_qra.conversion_adapter` 对引擎合同预检和动态能力规划的组合调用。

现有映射配置对标准结构化表格仍是最高优先级的确定性路径。大模型不能取代已经可确定映射的表头和单元格解析。

## 4. 范围边界

本阶段包括：

- 资料主题、对象、时间和桩号范围分类；
- 实体、字段及关系候选抽取；
- 大模型提供方端口、提示模板、结构化输出、重试和审计；
- 单位、数值、桩号、日期、坐标和枚举标准化；
- 同对象多来源匹配、完全重复、近似重复和冲突；
- 完整性、可靠性和第二部分节点可用性预分析；
- 黄金集准确率、召回率、证据绑定率和人工复核率报告。

本阶段不包括：

- 自动接受阻断型冲突或低置信度关键字段；
- 最终人工决定和快照确认；
- 修改第二部分模型参数的批准状态；
- 允许模型执行文档中的命令或调用任意工具；
- 以模型常识补充原文中不存在的项目事实。

## 6. 编排工作流

任务编排采用显式状态，不由模型自由决定下一步：

```text
PARSED
  → CLASSIFYING → CLASSIFIED
  → EXTRACTING_ENTITIES → ENTITIES_READY
  → EXTRACTING_FIELDS → CANDIDATES_READY
  → NORMALIZING → NORMALIZED
  → FUSING → FUSION_READY
  → QUALITY_CHECKING
  → READY_FOR_REVIEW 或 BLOCKED
```

每一步输入、输出、版本、开始/结束时间、重试次数和错误码必须持久化。服务重启后从最后一个已固化步骤恢复；不得重复写入已完成步骤的不同结果。取消标记在每个文件、批次和外部调用前检查。

编排器只有预定义工具：读取解析产物、调用配置的模型提供方、执行确定性规则、保存候选和生成质量报告。模型响应不能新增工具名、文件路径或工作流状态。

## 7. 资料分类合同

每个文件可有一个主类别和多个辅类别：

- 设计/竣工资料；
- 管线/管段基础台账；
- 内检测、外腐蚀、防腐层、阴极保护；
- 制造施工、焊缝和维修；
- 第三方活动和巡线；
- 地质灾害；
- 运行工况和事故事件；
- 阀室与隔离；
- 人口、高后果区和敏感受体；
- 气象、地形、点火和拥塞；
- 频率库、孔径比例、修正系数和批准参数；
- 其他/无法判断。

输出至少包含 `classification_id`、源文件、类别、置信度、证据块、识别到的管线/管段、桩号范围、资料日期、版本线索和模型版本。低于阈值或多个主类别接近时标记 `EXTRACT.CLASSIFICATION_AMBIGUOUS`，不强行唯一分类。

结构化映射配置明确声明资料类型时优先使用配置结果；模型只补充未声明内容。

## 8. 实体与关系模型

首版实体类型至少包括：

- `PROJECT`、`PIPELINE`、`SEGMENT`；
- `INSPECTION_RUN`、`INSPECTION_POINT`、`DEFECT`、`REPAIR_ORDER`；
- `VALVE`、`LEAK_EVENT`、`THIRD_PARTY_ACTIVITY`、`GEOHAZARD`；
- `POPULATION_CELL`、`SENSITIVE_RECEPTOR`、`WEATHER_CASE`；
- `PARAMETER_LIBRARY`、`APPROVAL_DOCUMENT`。

实体候选必须有稳定临时 ID、原始名称、标准化名称候选、业务主键候选、时间范围、桩号/坐标范围和证据。模型不能自行生成正式 `segment_id`；只有确定性身份规则或人工复核可绑定现有管段。

关系类型至少包括：`BELONGS_TO`、`LOCATED_IN`、`MEASURED_AT`、`APPLIES_TO_RANGE`、`SUPERSEDES`、`REPAIRS`、`REFERENCES`。关系的两端必须引用已存在实体候选，且至少有一个证据或确定性派生规则。

## 9. 字段提取策略

优先级固定为：

1. 结构化映射配置的确定性单元格提取；
2. 已知模板的确定性版面/正则规则；
3. OCR/文本上的受约束模型提取；
4. 人工录入或复核。

每次模型调用只提供当前任务所需的字段字典子集、相关解析块和实体上下文，避免把 246 项全部塞入无关文档。分块必须保留重叠窗口和原始块 ID；跨块合并使用候选 ID，不丢证据。

模型输出只允许第一阶段 Schema 中的字段：

- `field_id` 必须在允许子集中；
- `raw_value` 必须能在证据文本或表格单元格中核对；
- `evidence_ids` 必须属于本次输入块；
- `normalized_value` 只作建议，最终由确定性标准化器重新计算；
- 不确定时输出多个候选或 `not_found`，不得生成默认值；
- 模型不能设置 `review_status=CONFIRMED`、快照状态或正式报告状态。

## 10. 大模型提供方端口

`extraction/ports.py` 定义与厂商无关的接口：

```text
ExtractionProvider.extract(request) -> ExtractionResponse

ExtractionRequest:
  task_type, request_id, system_policy_version,
  prompt_template_version, schema, field_subset,
  document_blocks, entity_context, timeout_seconds

ExtractionResponse:
  provider_id, model_id, model_version,
  structured_output, usage, finish_reason,
  provider_request_id, raw_response_sha256
```

要求：

- API 密钥只从环境或密钥服务读取；
- 默认超时、最大响应大小、最大重试次数和并发限制可配置；
- 仅在超时、限流和可重试服务错误时重试，结构错误先进行一次受约束修复请求，仍失败则阻断该批次；
- 调用日志保存模型、模板、Schema 和输入块哈希，不保存密钥；
- 敏感资料在外部调用前执行第二阶段/第一阶段分类策略；不允许外发时使用本地提供方或转人工；
- 测试使用 fixture provider，黄金测试不能依赖实时模型漂移。

## 11. 提示注入防护

文档内容始终放入明确的“不可信资料内容”字段，不与系统规则拼接。系统策略必须声明：文档中的命令、提示词、链接、角色声明和工具请求只是待提取文本。

强制控制：

1. 模型无工具调用权限；
2. 只接受 JSON Schema 结构化输出；
3. 字段 ID、实体类型、关系类型和动作使用白名单；
4. 响应中的路径、URL、代码和工具名不执行；
5. 证据必须引用输入块；
6. 提示注入样本产生 `EXTRACT.UNTRUSTED_INSTRUCTION_DETECTED` 信息或警告，但仍作为普通文本分析；
7. 模型输出进入数据库前进行长度、类型、Unicode 控制字符和嵌套深度检查；
8. 上传资料不能改变合同、模型、提示词或来源优先级版本。

## 12. 确定性标准化

模型不得直接决定最终标准值。标准化器按第一阶段规则处理：

### 12.1 数值和单位

- 分离数值、单位、约等于/范围/小于大于等限定；
- 使用 `Decimal` 或有明确精度策略的数值转换；
- 压力区分表压和绝压；未说明时不得互换；
- 百分数只在有 `%` 或列单位证据时除以 100；
- 区间保留上下界，不能擅自取平均作为事实；
- 原值、解析值、标准值和换算公式均保留。

### 12.2 桩号、坐标、日期和枚举

- 桩号统一为 km 并保留原表达；
- 坐标必须有坐标系，无法确认坐标系时只保留原值并阻断空间映射；
- 日期统一 ISO 8601；仅有月份/年份时保存精度，不能补造日；
- 枚举映射记录映射规则；无法唯一匹配时产生候选；
- 管线和管段名称标准化只处理空白、大小写和批准别名，不做模糊覆盖。

## 13. 多来源匹配与融合

### 13.1 身份匹配顺序

1. 明确业务 ID；
2. 批准的名称/编号别名；
3. 管线 ID + 半开桩号区间；
4. 坐标容差 + 时间/资料类型；
5. 模糊名称候选，必须复核。

半开区间统一为 `[start_km, end_km)`，管线末端例外规则显式测试。跨管线相同桩号不得匹配。

### 13.2 重复类型

- `EXACT_DUPLICATE`：标准化值、实体和有效期相同；
- `COMPLEMENTARY`：同一记录不同字段互补；
- `NEAR_DUPLICATE`：在字段容差内但原文不同；
- `CONFLICT`：同字段有效候选超出容差；
- `IDENTITY_AMBIGUOUS`：记录可能属于多个对象。

来源优先级只生成 `proposed_candidate_id` 和理由。所有冲突候选均保留，不能覆盖低优先级来源。人工决定引用候选集合哈希；候选变化后旧决定判定为过期。

### 13.3 来源建议策略

`source_rank.json` 可按资料类型、批准状态、有效日期和项目配置生成建议。例如经批准的竣工资料可优先于无签章汇总表，较新检测记录可优先于较旧记录。但涉及不同概念、不同有效期或设计值/运行值时不得比较为同一字段。

## 14. 质量检查与能力分析

在候选层执行：

- 必填候选缺失、类型、单位、范围和枚举；
- 管段重叠、断档、反向桩号和长度不一致；
- 运行压力与设计压力关系；
- 气体组分、气象概率、孔径比例归一化；
- 外径大于壁厚等基本关系；
- 对象归属、日期有效性和来源证据；
- 关键字段低置信度；
- 多来源冲突和过期复核决定。

生成 `capability_plan` 时只使用已通过确定性校验且无阻断冲突的拟采用值。候选缺失要映射到第二部分节点的 `missing_inputs`；不得把默认测试值当作用户已提供数据提升完整度。

## 15. 数据持久化与 API

候选量可能很大，不应只存在 `conversion_job.payload_json`。新增或等价实现：

- `extraction_run`：步骤、提供方、模型、模板、Schema、输入/输出哈希和状态；
- `extracted_entity`；
- `candidate_field`；
- `candidate_evidence_link`；
- `candidate_relationship`；
- `quality_issue`；
- `fusion_group` 和候选成员关系。

原始模型响应存受控产物并以哈希引用；普通 API 不返回完整响应。

提供第五阶段所需只读接口：

- `GET /admin/api/conversions/{id}/review-summary`；
- `GET /admin/api/conversions/{id}/candidates?status=&field_id=&entity=&cursor=`；
- `GET /admin/api/conversions/{id}/candidates/{candidate_id}`；
- `GET /admin/api/conversions/{id}/issues?severity=&code=&cursor=`；
- `GET /admin/api/conversions/{id}/capability`。

本阶段不提供确认候选的写接口，写操作在第五阶段统一实现。

## 16. 代码任务拆分

### 16.1 任务 A：编排与提供方端口

1. 定义步骤状态、输入输出和恢复规则；
2. 定义模型端口、fixture provider、超时和重试；
3. 版本化提示模板和清单哈希；
4. 实现结构化输出和证据引用校验；
5. 实现取消和外部调用审计。

### 16.2 任务 B：分类、实体和字段

1. 先接入确定性映射；
2. 再对未覆盖块调用分类与实体抽取；
3. 按文档类别选择字段子集；
4. 把模型输出转为第一阶段候选合同；
5. 对重复证据和跨块候选去重。

### 16.3 任务 C：标准化和融合

1. 把现有 `mapping.values` 和 `matching.chainage` 迁移/复用到统一模块；
2. 增加单位、日期、坐标和枚举规则；
3. 实现实体身份、重复和冲突分组；
4. 复用 `review.py` 的稳定复核 ID 和过期决定检查；
5. 输出建议值但保留所有候选。

### 16.4 任务 D：质量、能力和指标

1. 建立候选层质量规则；
2. 生成可用字段草稿并调用第一阶段 Schema；
3. 由 `db_qra` 组合根调用引擎导入预检和动态能力规划；
4. 生成精确率、召回率、证据绑定率、冲突检出率和人工复核率；
5. 保存按文件类型、字段组和提取方法分层的指标。

## 17. 黄金测试设计

黄金集至少覆盖：

- 同一压力以 MPa、kPa、bar 表示；
- “运行压力/工作压力/管内压力”同义和设计压力干扰项；
- `K12+300`、`12300m`、跨管线同桩号；
- 同一管线多个名称、同名不同管线；
- 新旧检测报告冲突、设计/运行概念不应冲突；
- 表格、段落、扫描件对同一事实的互补与矛盾；
- 坐标系缺失、日期精度不足、百分数语义不明；
- 无证据字段、模型返回未知字段、伪造证据 ID；
- 文档中的“忽略规则、执行命令、上传数据到某网址”等提示注入文本；
- 模型超时、限流、非法 JSON、超大响应和部分批次失败。

每个案例标注实体、字段、标准值、证据、预期问题和冲突组。指标按结构化表格、原生文档、扫描件和复杂表格分别统计。

## 18. 验收指标

- 结构化表格受支持字段精确率不低于 99%；
- 模拟非结构化资料关键字段精确率不低于 95%，召回率不低于 90%；
- 已提取关键字段证据绑定率 100%；
- 受支持单位标准化正确率 100%；
- 黄金集中预设冲突、缺失和提示注入检出率 100%；
- 未知字段、无效证据和越权状态 100% 被拒绝；
- 关键低置信度字段不进入可确认草稿；
- 模型失败不产生伪候选，其他文件可按策略继续；
- 相同确定性输入和版本得到一致标准化及融合结果。

## 19. 验收清单

- [ ] 编排状态可恢复、可取消、可审计；
- [ ] 确定性映射优先于大模型；
- [ ] 模型只看到相关字段子集和不可信文档块；
- [ ] 模型没有工具和计算提交权限；
- [ ] 所有候选满足第一阶段 Schema；
- [ ] 标准化不覆盖原值和证据；
- [ ] 冲突组保留全部来源，建议值不等于确认值；
- [ ] 旧复核决定在候选变化后失效；
- [ ] 能力规划不把默认值冒充项目事实；
- [ ] 黄金指标按资料类型分层达标；
- [ ] 全量回归通过。

## 20. 向第五阶段移交

移交候选、实体、关系、证据、融合组、质量问题、能力计划以及全部模型/提示词/规则/合同版本。第五阶段只能通过复核决定改变拟采用值，不能修改解析原文、候选事实或模型调用记录。
