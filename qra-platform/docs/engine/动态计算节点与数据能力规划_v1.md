# 动态计算节点与数据能力规划 v1

## 1. 改造目标

旧流程要求输入先满足完整人员QRA案例合同，然后按固定顺序运行全部步骤。任一关键数据段缺失，完整流程即被阻断，因而部分完整性数据无法形成风险值。

动态流程将算法拆成有版本、有标准来源、有输入合同、有输出合同的节点。系统先识别数据，再规划可运行节点；某个节点缺数据或发生运行错误，不影响没有依赖关系的其他节点。只要存在可识别管段，`adaptive_evidence_qra`就以标准公式骨架和当前证据形成风险值；完整人员QRA可用时，结果展示节点自动优先选用完整QRA。

## 2. 节点状态

| 状态 | 含义 |
|---|---|
| `COMPLETED` | 输入和依赖满足，节点已生成JSON；如启用图表也已生成SVG |
| `SKIPPED_MISSING_INPUT` | 节点缺少必需字段，未执行算法 |
| `SKIPPED_DEPENDENCY_FAILED` | 本节点的数据具备，但上游节点没有完成 |
| `FAILED_ISOLATED` | 节点运行时发生参数或数值错误，错误被隔离 |

任务状态：

- `PASS`：所规划节点全部完成；
- `PARTIAL`：完成了部分算法，同时有节点跳过或隔离失败；
- `PARTIAL_DATA_ONLY`：只能完成数据盘点和指标覆盖分析；
- `BLOCK`：没有任何节点能够完成。

## 3. 不是按“10类/20类”机械计数

系统会报告客户提交了多少顶层数据段、识别到多少指标组，但算法匹配依据是具体字段合同。例如：

```text
客户提供20类记录，但缺少运行压力
→ AQ/T 3046泄漏源项不可运行

客户只提供10类记录，但包含管段、频率库和批准的K_j
→ SY/T 6891.2失效频率节点可以完整运行

客户只提供11类阴保、内检测、运行与高后果目标记录
→ 自适应证据定量风险节点更新管段失效概率并计算PLL筛查估计、上下界和风险矩阵
```

每个跳过节点都会在`capability_report.json`中给出`missing_inputs`，输入层可以直接把这部分转换成对用户的补数问题。

## 4. 动态DAG

```text
data_inventory
├─ indicator_coverage
└─ segment_geometry
   ├─ failure_frequency
   ├─ leak_point_discretization
   ├─ aqt3046_source_term
   │  └─ jet_fire_thresholds
   ├─ gbt34346_annex_c
   └─ adaptive_evidence_qra
      └─ risk_matrix（证据定量结果）

failure_frequency + leak_point_discretization + aqt3046_source_term
└─ human_qra
   └─ risk_matrix（自动覆盖为完整人员QRA结果）
```

当前按拓扑顺序执行节点，属于单进程顺序执行；但已经不再是固定单流程。后续可在不改变节点合同的情况下，把没有依赖关系的节点和管段场景切换为进程池或任务队列并行。

## 5. 标准与算法边界

- `failure_frequency`：SY/T 6891.2-2020附录A；
- `leak_point_discretization`：SY/T 6891.2-2020的管道QRA空间离散框架；
- `aqt3046_source_term`：AQ/T 3046-2013 E.13-E.22；
- `jet_fire_thresholds`：AQ/T 3046-2013 E.57-E.59；
- `gbt34346_annex_c`：GB/T 34346-2017附录C独立校核；
- `adaptive_evidence_qra`：采用GB/T 34346附录C表C.1、表C.24和式C.40-C.42作为频率/孔径/风险骨架，调用AQ/T 3046泄漏、热辐射和人员伤害公式；
- `human_qra`：SY/T 6891.2主框架调用AQ/T 3046人员后果公式；
- `risk_matrix`：结果展示节点，不替代IR或批准的F-N接受准则。

阴极保护、CIPS、DCVG、土壤、内检测和维修等数据不仅会被识别，还会进入`adaptive_evidence_qra`的证据更新层。该层不是标准规定的固定权重：每个响应项、参考值、尺度、系数和边界都登记在`adaptive_evidence_qra_v1.json`中，可由行业或项目失效数据替换和校准。缺失指标按中性贡献边缘化，并通过更宽的不确定性带反映证据不足。

节点优先读取`engineering_indicators`标准化观测；如果该汇总层不存在，会直接从同步断电、CIPS、DCVG、土壤、试片、内检测和维修工单原始记录中聚合所需量。因此输入层可以逐步完善标准化映射，不会因暂时缺少汇总层而失去风险结果。

风险结果分两级：

- `EVIDENCE_CONDITIONED_SCREENING_ESTIMATE`：现有证据定量筛查估计，输出PLL、排序、矩阵和不确定性带，但不自动作正式接受性判断；
- `FULL_SPATIAL_HUMAN_QRA`：数据满足完整主链后生成IR、F-N、PLL和完整空间结果，并优先覆盖筛查结果进入风险矩阵。

## 6. 输出合同

`execution_plan.json`保存运行前计划；`dynamic_manifest.json`保存运行后实际状态。`capability_report.json`面向输入层和前端，核心字段为：

```json
{
  "completed_node_ids": [],
  "skipped_node_ids": [],
  "failed_node_ids": [],
  "available_outputs": [],
  "unavailable_outputs": [],
  "missing_inputs": [],
  "detected_groups_without_registered_calculation": []
}
```

每个已完成节点写入`nodes/<node_id>.json`，因此下游可以只读取失效频率、源项或完整人员QRA结果，无需解析一份包含所有领域的固定大JSON。

动态输出合同 v1.2.0 在 `capability_report.json.risk_result` 中分别登记 `pll_available`、`individual_risk_available` 和 `fn_curve_available`。缺少空间受体时，证据条件化模型仍可用明确标识的人口密度先验形成 PLL 筛查估计，但 IR 使用 `null` 和 `NOT_CALCULATED_MISSING_SPATIAL_RECEPTORS`，项目 F-N 使用 `NOT_CALCULATED_MISSING_POPULATION_DISTRIBUTION`，不再以数值 0 或先验人口曲线冒充真实项目结果。复合节点即使被上游依赖阻断，也会执行安全预检并报告自身数据合同缺口。

## 7. 扩展新标准或新数据算法

新增算法时需要登记：

1. 节点ID和版本；
2. 标准及条款来源；
3. 必需字段及是否要求覆盖全部管段；
4. 上游依赖节点；
5. 结构化输出ID；
6. 算法函数和单元测试；
7. 可选图表函数；
8. 正式启用状态与阻断条件。

完成登记后，数据能力规划器会自动把它纳入全量匹配，无需修改固定主流程。
