问题清单和严重级别
P0-01：完整物理链缺少独立外部基准
- 复现/输入：查找标准案例、历史工程、可信表格、授权软件输出。
- 预期：至少一套独立完整算例，可逐层比较源项、后果、IR、FN、PLL。
- 实际：没有可用外部结果；多项核心物理链仍为 provisional。
- 影响：不能证明模型工程精度。
- 建议：准备经批准的盲算案例及逐场景输出。
- 阻止下一阶段：是。
P0-02：天然气组分未参与物理计算
- 复现：把94.6%甲烷输入替换为归一的100%氮气。
- 预期：摩尔质量、热值、源项或热后果应发生显著变化，或明确拒绝不支持的组分。
- 实际：PLL、IR完全不变。
- 影响：关键输入断链，真实气质差异无法传递到后果。
- 证据：[validation.py (line 79)](/D:/风险定量评估/计算引擎/qra_engine/validation.py:79)、[physical_consequence.py (line 43)](/D:/风险定量评估/计算引擎/qra_engine/physical_consequence.py:43)。
- 建议：建立气质→物性/热值的唯一权威参数路径，并增加变形测试。
- 阻止下一阶段：是。
P0-03：同输入可复现哈希不一致
- 复现：相同20管段 JSON 文件版、数据库版各运行两次。
- 预期：权威节点文档和可复现哈希一致。
- 实际：文件/DB审计哈希不同；数据库重复任务的结果哈希也因运行时间和任务 ID 不同。
- 影响：无法用哈希证明相同输入产生同一结果。
- 建议：明确“数值结果哈希”和“运行审计清单哈希”，前者排除时间、任务 ID，并统一数组/对象规范化和浮点聚合顺序。
- 阻止下一阶段：是。
P1-01：后端业务校验不足
- 复现：上传 {}、空管段、无关 JSON、倒置里程、错误单位等。
- 预期：前端及导入接口均返回结构化400错误，不写入数据库。
- 实际：多数返回200/201并写入；重复编号最终变成数据库500。
- 影响：非法数据可污染快照并触发无意义计算。
- 建议：预检和导入共用完整输入合同校验。
- 阻止下一阶段：是。
P1-02：关键自动化回归未运行
- 复现：执行两个 unittest 命令。
- 预期：测试数据路径有效。
- 实际：7个引擎测试和全部数据库E2E因 examples 路径不存在而报错。
- 影响：上传—入库—还原—计算—查询链缺少自动回归保障。
- 建议：在后续整改中统一测试夹具定位，并重新执行原测试。
- 阻止下一阶段：是。
P1-03：最终报告丢失或伪零化关键结果
- 复现：打开完整20管段运行报告并与 API/数据库比较。
- 预期：主导场景、影响距离、上下界忠实显示；缺失值显示“不适用/未计算”。
- 实际：主导场景“—”、距离0 m、空上下界显示0–0。
- 影响：可能误导报告使用者判断后果及不确定性。
- 建议：按结果层级选择权威节点源，禁止将 null 默认为物理零。
- 阻止下一阶段：是。
P2-01：预检失败后旧界面状态残留
- 复现：先上传有效11类 JSON，再上传损坏 JSON。
- 预期：旧预览、指纹、名称清空，两个按钮禁用。
- 实际：显示“预检失败”，但旧预览、指纹、名称、可运行节点和两个按钮仍保留。
- 影响：界面状态混淆；当前 uploadPayload 已清空，因此未观察到错误数据实际提交。
- 证据：[admin_ui.py (line 164)](/D:/风险定量评估/数据库版计算引擎/db_qra/admin_ui.py:164)。
- 建议：失败路径调用统一 reset，并禁用操作按钮。
- 阻止下一阶段：否，但应与 P1 校验整改一并处理。
P2-02：文档和数据类别口径陈旧
- 复现：核对 README 路径、6类 manifest、上传预检和完整报告。
- 预期：路径、类别数及口径一致。
- 实际：README仍引用 examples 和旧 D:\Siga 路径；类别数存在6/4及报告0类等多种口径。
- 影响：维护和审计人员容易误判数据完整性。
- 建议：定义唯一“数据类别”统计口径并同步文档。
- 阻止下一阶段：否。
