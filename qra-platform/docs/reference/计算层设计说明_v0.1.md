# 定量风险评估平台：计算层设计说明 v0.1

## 1. 先给结论

平台应当把“风险评估方法”实现为**可版本化、可追溯、可替换的模型包**，而不是把所有标准写进一个大公式。

当前标准文件中至少存在三类互不兼容的计算语义：

1. **安全能力评分型半定量模型**：控制措施得分越高，风险越低，例如 GB/T 27512—2011 的在用埋地钢质管道模型采用 `S = 100 - 加权安全得分`。
2. **危险程度评分型半定量模型**：危险因素得分越高，风险越高，例如现有《城镇燃气输配管道风险评估方法》团体标准稿采用 `S = Σ(wᵢ×sᵢ)`、`C = Σ(vⱼ×cⱼ)`、`R = S×C`，再通过 5×5 矩阵确定等级。
3. **概率后果型定量模型（QRA）**：以失效频率、泄漏场景、天气概率、点火概率和致死概率计算个人风险与社会风险，例如 SY/T 6891.2—2020。其主要输出不是简单的 5×5 矩阵，而是个人风险等值线、F-N 曲线、可接受性判定及 ALARP 分析。

因此，建议采用“双轨计算层”：

- **轨道 A：半定量评分引擎**，先作为首个可运行版本，快速打通区段、指标、得分、矩阵、风险因子和治理措施闭环。
- **轨道 B：定量 QRA 引擎**，复用相同的区段、数据质量、版本、审计和报告接口，增加失效频率、物理后果、个人风险、社会风险和不确定性计算。

平台可以统称“定量风险评估平台”，但每次计算结果必须明确标注 `qualitative`、`semi_quantitative` 或 `quantitative`，不能把评分法包装成概率型定量结果。

## 2. 平台总体边界

建议的平台逻辑链如下：

```text
自然语言/文档/GIS/台账/检测数据
            ↓
输入理解层：抽取事实、单位换算、实体对齐、证据定位、置信度
            ↓
标准化数据层：资产—管线—区段—观测值—证据—时间
            ↓
计算层：模型选择—校验—计算—分级—不确定性—贡献度—重算
            ↓
结构化风险结果：区段风险、风险矩阵/IR/F-N、主导因子、审计轨迹
            ↓
结果处理层：治理措施、情景对比、优先级、报告、任务闭环
```

计算层不直接读取自然语言。输入理解层必须先生成“事实 + 单位 + 适用时间 + 证据 + 置信度”。例如“这条管子比较老”不能直接参与计算，必须转换为：

```json
{
  "field": "commissioning_date",
  "value": "2002-06-01",
  "source": "竣工资料第12页",
  "confidence": 0.98,
  "status": "verified"
}
```

无法唯一结构化的描述必须形成待确认项，不能静默猜值。

## 3. 计算层的十个核心模块

### 3.1 适用性与模型选择器

根据资产类型、介质、材质、设计/工作压力、管径、生命周期阶段、敷设方式、评价目的和地区选择模型。

模型选择必须返回：

- 推荐模型及版本；
- 适用条款匹配结果；
- 不适用条件；
- 候选模型之间的差异；
- 是否属于严格按标准计算或企业校准模型。

同一对象可以运行多个模型，但结果必须并列展示，不能混合得分。

### 3.2 动态区段划分器

区段是计算最小单元。区段边界应由关键属性变化点动态生成，包括：

- 压力、管径、壁厚、材质、防腐层、建设/投用时间；
- 地区等级、人口密度、建筑物与重要设施；
- 敷设方式、埋深、穿跨越、阀室/阀门边界；
- 土壤腐蚀性、杂散电流、阴极保护、防腐层状况；
- 检测结果、缺陷分布、事故或泄漏历史；
- 管理区域或标准明确要求的最大连续长度。

区段划分要保存 `split_reason`。相邻区段可合并时，也要保存合并依据。这样报告才能解释“为什么这 500 米单独成为高风险段”。

### 3.3 输入数据校验器

至少实现六类校验：

- 类型校验：数值、枚举、日期、空间几何；
- 单位校验：MPa、kPa、mm、m、kg/s、次/(km·a) 等；
- 范围校验：工作压力不能为负，投用日期不能晚于评价日期；
- 逻辑校验：工作压力不应无说明地大于设计压力；
- 条件必填：只有埋地段才要求埋深，只有气体泄漏才进入气体扩散模型；
- 标准适用性校验：例如 DB34/T 4280—2022 仅适用于其规定压力、温度和管径范围内的在役 PE 燃气管道。

### 3.4 半定量规则引擎

用于表格评分、分段函数、加权求和、扣分/加分、上下限和强制覆盖规则。

规则不写死在业务代码中，而应保存为模型定义：

```yaml
rule_id: C1.max_working_pressure
input: segment.max_working_pressure
unit: MPa
operator: interval_lookup
intervals:
  - {min: 0, max: 0.1, min_inclusive: true, max_inclusive: false, score: 15}
weight: 0.12
source_ref: "附录B 表B.1 C1"
```

禁止使用动态 `eval`。公式应解析为受控表达式树，物理模型通过有版本的函数插件实现。

### 3.5 失效频率引擎

用于真正的定量评价。至少支持三种方法：

- 基于历史失效数据修正；
- 结构可靠性分析；
- 故障树分析。

输出不仅是总频率，还要保留失效模式和孔径场景频率，例如小孔、中孔、大孔、完全破裂，以及外腐蚀、内腐蚀、应力腐蚀开裂、制造施工缺陷、第三方损坏、自然与地质灾害、误操作等贡献。

### 3.6 失效后果引擎

定量链路按事件顺序拆解：

```text
失效场景 → 泄漏速率/泄漏量 → 扩散 → 点火 →
喷射火/池火/蒸气云爆炸/闪火/安全扩散 →
热辐射/超压/浓度 → 人员死亡概率与财产/环境影响
```

每一步都应输出中间结果，不能只返回最终等级。第三方后果软件的结果可以接入，但必须记录软件名称、版本、输入文件摘要、模型设置和结果文件哈希。

### 3.7 风险聚合与分级器

该模块必须区分不同模型的聚合语义：

- 加权安全得分后取补数；
- 加权危险得分；
- `R=S×C`；
- 5×5 风险矩阵；
- 绝对风险区间和相对风险区间；
- 个人风险 `IR`；
- 社会风险 `F-N`；
- ALARP/可接受性判定。

原始值、等级值和展示颜色必须分开保存。颜色只是 UI 属性，不能作为计算数据。

### 3.8 不确定性与敏感性分析器

每个输入需带数据质量等级和不确定性。计算层至少输出：

- 缺失数据清单；
- 使用的标准缺省值或保守假设；
- 结果置信等级；
- 对结果最敏感的输入；
- 临界值附近的等级稳定性；
- 定量模型的参数分布、分位数或蒙特卡罗结果（需要时）。

缺失值默认按 0 分处理会系统性低估或高估风险，应禁止。只有标准明示的缺省值才可自动使用，并标记 `assumption_used=true`。

### 3.9 风险贡献度与措施模拟器

结果处理层不能仅凭风险等级生成泛化建议。计算层要先给出可解释的贡献度：

- 半定量模型：评分项对 `S`、`C` 和最终等级的贡献；
- 定量模型：失效模式、孔径场景、天气、点火事件和受灾体对风险的贡献；
- 强制覆盖项：是什么条件直接把 `S` 调到 100 或把 `C` 调到 150；
- 最小改变集：改变哪些可控输入可将风险降到目标等级。

治理措施必须映射到可改变的计算参数。例如“增加巡检频率”应改变巡检频率规则和对应失效频率修正因子。措施实施前后各运行一次模型，形成固有风险、当前剩余风险和措施后预计风险三组结果。

### 3.10 运行审计与可重复计算

每次 `calculation_run` 应冻结：

- 模型 ID、标准编号、模型版本、规则版本；
- 输入快照与证据引用；
- 单位换算过程；
- 每个公式节点的输入、输出和来源条款；
- 使用的缺省值、人工覆盖和审批人；
- 代码版本、运行环境、随机种子；
- 结果摘要及哈希。

历史结果不可覆盖，只能创建新运行并建立 `supersedes` 关系。

## 4. 建议的数据对象

| 对象 | 作用 | 关键字段 |
|---|---|---|
| `Asset` | 被评估对象 | 类型、介质、材质、设计参数、空间范围 |
| `Segment` | 最小评价单元 | 起止里程、几何、属性快照、划分原因 |
| `Observation` | 可参与计算的事实 | 字段、值、单位、时间、质量、状态 |
| `Evidence` | 事实依据 | 文件、页码/表格/GIS图层、摘要、哈希 |
| `ModelDefinition` | 模型元数据 | 标准、版本、适用范围、算法类型、状态 |
| `RuleDefinition` | 可配置规则 | 条件、得分、权重、单位、条款来源 |
| `Scenario` | 失效与后果场景 | 模式、孔径、天气、点火、受灾体 |
| `CalculationRun` | 一次不可变运行 | 输入快照、模型版本、状态、审计信息 |
| `IndicatorResult` | 细项结果 | 原值、标准化值、得分、贡献、解释 |
| `RiskResult` | 区段总体结果 | S、C、R、等级、IR、F-N、可信度 |
| `MitigationOption` | 风险治理方案 | 目标参数、成本、工期、预计风险降低 |
| `ValidationIssue` | 阻断或警告 | 严重性、字段、原因、解决状态 |

`Observation` 不应只有一个当前值。管龄、压力、人口、埋深、阴极保护电位和巡线频率都具有时间性，应使用有效期或观测时间保存历史。

## 7. 建议的首个可运行模型

### 7.1 MVP 对象

建议首个严格模型选择：

> **在用埋地钢质城镇燃气管道，GB/T 27512—2011 基本模型。**

原因：

- 适用对象与天然气/城镇燃气管道示例一致；
- 失效可能性、失效后果、风险值、绝对等级和相对等级形成完整闭环；
- 存在明确的强制覆盖条件；
- 结果可以直接支持区段排序、主导因子解释和措施后重算；
- 比从物理后果模型起步更容易验证平台的模型版本、规则、审计和报告接口。

GB/T 27512—2011 在用阶段模型的核心语义为：

- 第三方破坏、腐蚀、设备（装置）及操作、本质安全质量四类安全得分；
- 城市燃气管道失效可能性：`S = 100 - (0.30S31 + 0.30S32 + 0.10S33 + 0.30S34)`；
- 后果从短期危害性、最大泄漏量、扩散性、人口密度、沿线环境、泄漏原因和供应中断影响七方面求和；
- `R = S×C`；
- 绝对等级边界：`[0,3600)`、`[3600,7800)`、`[7800,12600)`、`[12600,15000]`；
- 相对等级边界基于同一管道的 `Min/Max`，按 `6/25`、`13/25`、`21/25` 分割；
- 特定不符合项可将 `S` 强制调整为 100，特定后果条件可将 `C` 强制调整为 150。

必须同时输出绝对等级和相对等级。相对等级只表示同一管道内部排序，不能代替绝对可接受性判断。

### 7.2 第二个模型

建议第二个模型选择 DB34/T 4280—2022 的在役 PE 燃气管道模型，以验证：

- 同一引擎支持不同材质；
- 条件适用性校验；
- 不同评分项和模型结构；
- 与钢质管道并行输出而不混分。

### 7.3 真正定量模型

随后实现 SY/T 6891.2—2020 的 QRA 管线：

1. 管段与网格划分；
2. 小孔、中孔、大孔和破裂等 LOC 场景；
3. 历史修正、结构可靠性或故障树失效频率；
4. 泄漏速率/泄漏量；
5. 扩散、点火、火灾/爆炸事件树；
6. 热辐射、超压和人员致死概率；
7. 个人风险求和与等值线；
8. 社会风险累计与 F-N 曲线；
9. 可接受准则和 ALARP；
10. 风险减缓措施前后重算。

SY/T 6891.2—2020 给出了总体链路和部分概率/伤害准则，但后果计算仍会引用其他模型或规范，不能仅凭这一份标准独立完成全部物理模型。正式开发前需要形成“公式来源清单”，逐项确认泄漏、扩散、火灾、爆炸和致死概率模型。

## 8. 已发现、必须先处理的标准实现风险

### 8.1 团体标准稿不能直接原样编码

当前 Word 稿存在至少以下待审问题：

- 球墨铸铁失效可能性五个一级权重为 `10%+15%+30%+10%+30%=95%`，未达到 100%；
- 最高工作压力若干区间在 0.4、0.8、1.6、2.5、4.0 MPa 等边界使用了重叠的闭区间；
- `S=0` 或 `C=0` 未被 `0<S≤20`、`0<C≤20` 的等级表覆盖；
- 文本给出 `R=S×C`，但最终等级由 S/C 等级矩阵判定，未给出仅由 R 确定等级的规则；
- 规范性引用文件中 GB/T 27512 重复出现；
- 部分措辞和编号仍有草稿痕迹。

这些问题应形成“标准问题单”，由标准编制人员或领域专家确认。平台不能自行修正规范后仍声称严格符合该标准。

### 8.2 不同模型的得分方向相反

GB/T 27512 的子项多为安全能力得分，最终用 100 减去；团体标准稿的子项多为危险程度得分，直接加权求和；Q/SY 05676.1 的相对风险值又有自己的方向和区间。模型定义必须显式声明：

```yaml
score_semantics: protection_score | hazard_score | probability
risk_direction: higher_is_worse | lower_is_worse
aggregation: complement_of_weighted_sum | weighted_sum | probability_sum
```

### 8.3 严格标准模型与企业校准模型必须分开

GB/T 27512—2011 的部分社会经济评分条件具有明显年代背景。平台可以实现：

- `STRICT_STANDARD`：逐条忠实实现，用于标准符合性计算；
- `ENTERPRISE_CALIBRATED`：经专家和数据校准后的企业模型。

两者必须使用不同模型 ID，报告中不能混称。

## 9. 风险治理结果如何从计算层生成

“3 段最高风险管道”之后，系统不应直接让大模型自由生成建议。正确流程是：

1. 找出三段的强制覆盖项、主导失效模式和主要后果因素；
2. 从措施库筛选能改变这些因素的措施；
3. 把措施转成参数变化和实施约束；
4. 重新计算措施后的风险；
5. 比较风险降低量、成本、工期、停输影响和可能引入的新风险；
6. 输出有依据的措施组合与优先级；
7. 实施后用实际数据再次评估，替换“预计剩余风险”。

治理结果建议至少包含：

- 风险段位置、长度、当前等级；
- 主要风险来源及计算贡献；
- 立即措施、工程措施、管理措施和监测措施；
- 每项措施对应的标准条款和被改变的计算参数；
- 单项措施与组合措施的预计剩余风险；
- 成本/收益、优先级、责任人、完成期限；
- 验收证据和再评估触发条件。

## 10. 计算层验收标准

每个模型上线前至少具备以下测试：

- 标准中的示例或人工核算结果可复现；
- 每个区间的下界、上界、临界点各有测试；
- 权重合计、分项合计和总分范围不变量测试；
- 强制覆盖条件测试；
- 单位换算前后结果一致；
- 同一输入、模型版本和随机种子结果完全一致；
- 对危险因素恶化的单调性测试；
- 缺失值、冲突值和过期值不会静默进入计算；
- 相对等级在 `Min=Max` 等退化情形下有明确处理；
- 与独立 Excel/人工计算或经认可的软件交叉验证；
- 结果中的每个分数可以追溯到输入证据和标准条款。

## 11. 推荐实施顺序

### 里程碑 A：模型框架

- 建立统一对象、单位系统、模型注册表、规则表达式和计算审计；
- 完成模型适用性检查和区段接口；
- 定义输入/输出 JSON Schema；
- 建立缺失值与人工确认机制。

### 里程碑 B：首个半定量闭环

- 实现 GB/T 27512—2011 在用埋地钢质城市燃气基本模型；
- 输出绝对/相对等级、贡献度和高风险段排序；
- 建立措施映射和措施后重算；
- 用人工算例形成黄金测试集。

### 里程碑 C：多材质和矩阵模型

- 接入 DB34/T 4280—2022 PE 模型；
- 在团体标准问题确认后接入钢质、PE、球墨铸铁 5×5 矩阵模型；
- 验证同一资产可并行运行多个模型并清晰对比。

### 里程碑 D：定量 QRA

- 建立失效频率、LOC、扩散、点火、火灾/爆炸和伤害模型插件；
- 接入 GIS 人口网格与天气频率；
- 输出 IR 等值线、F-N 曲线和 ALARP；
- 与认可的后果分析软件或经过验证的算例交叉校核。

### 里程碑 E：智能输入与报告

- 自然语言和文档抽取只负责提出结构化候选事实；
- 人工确认关键输入后才允许正式运行；
- 报告生成基于结构化结果和措施模拟，不直接“凭语言生成结论”；
- 建立评估—整改—验收—再评估闭环。
