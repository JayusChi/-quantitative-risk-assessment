# 人工复核工作台

人工复核工作台把第四阶段产生的候选字段、证据、融合冲突和质量问题转成可审计的人工决定，
并在最终门禁通过后创建不可变输入快照。普通业务流程不需要编写或粘贴
`review_decisions JSON`。

## 进入工作台

1. 启动本机服务：`python -m db_qra serve`。
2. 打开 `http://127.0.0.1:8766/admin/`，进入“资料自动转换”。
3. 在转换任务行或详情中点击“打开复核工作台”。
4. 已确认任务需要调整时点击“创建复核新版本”；系统创建新会话，历史快照保持不变。

工作台地址为 `/admin/reviews/{conversion_job_id}/`。首次进入会创建会话，再次进入幂等恢复当前
可编辑会话。

## 三栏页面

- 左栏按阻断程度、影响节点、关键级别、冲突和置信度排列业务字段组，可搜索并筛选阻断、冲突、
  低置信度、缺失、已处理状态、字段组、来源和节点。
- 中栏并列显示当前字段的全部候选、规范化值、单位、来源、位置、提取方式、版本、置信度和质量问题，
  提供接受、手工修改、驳回、不适用和重新提取五种操作。
- 右栏显示可读证据。CSV/XLS/XLSX返回目标行附近的表格上下文；图片和PDF坐标证据返回带红色高亮框的
  安全PNG；DOCX和普通文本返回稳定结构位置、原文摘要和来源元数据。

窄屏下页面切换“字段、候选、证据”三个视图。按钮、表单、对话框和状态变化具有键盘焦点及基本
ARIA标记；保存时如果服务端返回 `REVIEW_REVISION_CONFLICT`，页面刷新最新会话，不覆盖新决定。

## 五种操作

| 操作 | 规则 | 对门禁的影响 |
|---|---|---|
| 接受候选 | 必须选择当前候选并填写原因；无效、过期或不属于该字段的候选会被拒绝 | 冲突或关键低置信度项可被显式解决 |
| 手工修改 | 按字段合同显示数值、日期、枚举、布尔、对象或数组控件；验证类型、单位、范围和枚举；标记为 `MANUAL_REVIEW` | 合法值成为组装输入；不伪造文档证据 |
| 驳回全部 | 保留所有原候选和证据，只新增不可变决定 | 必需字段继续阻断，不能把驳回解释成不存在 |
| 标记不适用 | 仅合同明确允许的非必需字段可用，必须说明业务原因 | 合法不适用被解决；必填字段仍阻断 |
| 请求重新提取 | 绑定当前字段、源文件或证据，生成 `QUEUED` 请求，不删除旧候选 | 请求本身不解决字段；新候选改变集合哈希后旧会话转为 `STALE` |

每次改动都插入新的 `review_decision`，通过 `supersedes_decision_id` 形成历史链，不更新原决定，也不
修改 `candidate_field`。

## 会话状态机

```text
OPEN → IN_REVIEW → READY_TO_CONFIRM → CONFIRMED
  └──────────── candidate_set_hash变化 ───────────→ STALE

历史管理状态：CANCELLED、SUPERSEDED
```

- `OPEN`：会话已创建，尚无人工决定。
- `IN_REVIEW`：至少保存过一项决定，最新门禁尚未通过。
- `READY_TO_CONFIRM`：最新服务端门禁为 `PASS`。
- `STALE`：候选集合已变化，旧决定不会套用；必须创建或恢复与新集合绑定的会话。
- `CONFIRMED`：快照已原子创建，会话不可继续修改。

同一转换任务同一时刻最多一个可编辑会话。会话使用单调递增的 `revision` 做乐观锁。

## 最终门禁

底部固定栏显示处理数、未解决数、阻断数、警告数、组装字段数、可运行节点和跳过节点。确认前服务端
重新执行门禁，不信任浏览器缓存。门禁至少绑定并检查：

- 目标范围内的冲突、关键低置信度、缺失、驳回和重提取请求；
- 采用的文档候选具有属于本任务的有效证据；
- 手工值有复核人、原因并能确定性归一化；
- 必填、不适用、单位、压力基准、坐标系、桩号边界和实体映射规则；
- 第一部分JSON Schema与 `qra_engine.validate_import_contract`；
- 目标动态节点可运行，非目标缺数作为明确补数清单；
- 正式报告限制、筛查层级、候选集合哈希和决定集合哈希。

门禁为 `BLOCKED` 时确认接口拒绝创建快照。通过后，确认对话框要求快照名称、确认人和理由，允许选择
是否立即排队计算及生成图表。

## 确定性与不可变性

业务哈希只包含候选业务身份、字段、实体、规范化值、单位、证据、提取/模型/提示词/规则版本，以及
有效决定的业务内容。当前时间、HTTP请求、数据库ID、UI排序和确认人不进入 `payload_sha256`。
因此相同候选集合、相同有效决定和相同版本生成相同JSON与快照业务哈希。

确认在一个SQLite事务中重新校验哈希和门禁、创建或复用快照、写两类来源记录、确认会话和转换任务、
写审计，并可选插入 `QUEUED` 计算任务。任一步失败都会回滚。数据库触发器禁止修改快照业务内容，
也禁止更新或删除历史复核决定和门禁记录。

调整已确认数据必须创建复核新版本。相同业务内容可复用已有快照，但每次确认都会新增
`input_snapshot_review_provenance`，记录转换任务、会话、门禁、候选/决定集合哈希、映射/合同/模型/
提示词/规则版本、确认人和原因。旧计算任务永久引用原 `snapshot_id`。

## API

| 方法与路径 | 作用 |
|---|---|
| `POST /admin/api/conversions/{job_id}/review-sessions` | 创建或恢复会话 |
| `GET /admin/api/review-sessions/{session_id}` | 会话、进度和最新门禁 |
| `GET /admin/api/review-sessions/{session_id}/items` | 分页筛选复核项 |
| `GET /admin/api/review-sessions/{session_id}/items/{review_item_key}` | 单项候选、证据、问题和操作 |
| `POST /admin/api/review-sessions/{session_id}/decisions` | 保存五类不可变决定 |
| `POST /admin/api/review-sessions/{session_id}/reextract` | 创建重新提取请求 |
| `POST /admin/api/review-sessions/{session_id}/gate` | 执行并持久化门禁 |
| `POST /admin/api/review-sessions/{session_id}/confirm` | 原子确认、快照及可选计算任务 |
| `GET /admin/api/review-sessions/{session_id}/evidence/{evidence_id}` | 证据元数据 |
| `GET /admin/api/review-sessions/{session_id}/evidence/{evidence_id}/preview` | 受控证据预览 |

证据读取同时匹配 `conversion_job_id` 和 `source_id`，接口不接受磁盘路径。兼容CLI仍可读取旧决定文件，
但它不是管理页面默认业务入口。

## 常见阻断原因

- 冲突候选尚未显式选择；
- 关键低置信度候选尚未人工确认；
- 必填字段缺失、被驳回或请求重新提取；
- 文档候选缺少证据或证据属于其他任务；
- 手工值类型、单位、范围或原因不合格；
- 候选集合变化导致会话过期；
- 目标节点仍缺少输入，或组装JSON未通过输入合同。

当前单机版没有企业身份、多人实时协同和电子签名。重新提取请求由提取执行器消费；未配置或未授权
外发时只保留排队记录，不会自行调用云端模型。
