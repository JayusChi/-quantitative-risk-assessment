# 阶段 2 生成与复现说明

## 1. 权威输入

- S00 标准案例：`tests/fixtures/qra_synthetic_case_v1.json`
- 阶段 1 字段来源节点矩阵：`resources/synthetic/full-chain-v1/field-source-node-matrix.csv`
- 动态节点实现：当前 `src/` 代码与模型规格

标准案例只用于确定性生成项目事实、ground truth 和期望结果，不作为阶段 3 的原始资料入口。

## 2. 生成器

- 主生成器：`tools/build_synthetic_source_pack.py`
- 工作簿构建器：`tools/build_synthetic_source_workbooks.mjs`
- `artifact-tool` 运行入口：`tools/run_synthetic_source_workbooks.mjs`

Python 依赖已登记在 `pyproject.toml`，包括 `python-docx` 和 `reportlab`。XLSX 使用 `@oai/artifact-tool` 创建、检查、渲染和导出。

## 3. 生成命令

先通过工作区依赖加载器取得 bundled Python 与 Node 路径。项目根目录下执行：

```powershell
$env:PYTHONPATH = 'src'
$node = '<workspace-dependencies>/node/bin/node.exe'
$python = '<workspace-dependencies>/python/python.exe'

& $python tools\build_synthetic_source_pack.py --node-executable $node
& .\.venv\Scripts\python.exe tools\build_synthetic_source_pack.py --check
& .\.venv\Scripts\python.exe -m unittest tests.unit.test_full_chain_stage2_source_pack -v
```

生成器会从 Node 可执行文件相邻的 `node_modules` 自动解析 `@oai/artifact-tool`。如使用自定义布局，可设置 `QRA_WORKSPACE_NODE_MODULES`，或用 `--workbook-launcher` 覆盖工作簿入口。

## 4. 输出目录

- 版本化规范：`resources/synthetic/full-chain-v1/stage2/`
- 用户可用产物：`workspace/outputs/m1-5-stage2-source-pack-20260901/`
- D00 ZIP：`workspace/outputs/m1-5-stage2-source-pack-20260901/S00_BASELINE_D00_CLEAN.zip`

`workspace/outputs` 可删除并重建；`resources/.../stage2` 是代码库中的规范验收基准。

## 5. 确定性合同

- 不调用随机数生成器，`random_seed=null`。
- 所有列表按目标路径、文件名或变体 ID 排序。
- JSON 使用 UTF-8、稳定键顺序和固定分隔符进行规范序列化。
- ZIP 成员排序固定，时间戳固定为 2020-01-01。
- 跨运行相等性使用 `business_content_sha256`；容器生成时间不纳入业务哈希。
- 11 节点结果另以 `numerical_result_sha256` 与 `full-contract-result-hashes.json` 的 361 字段物化基线核对；阶段 0 哈希仅作为补齐前历史记录保留。
- 单份资料包的文件完整性使用 Manifest 中的逐文件字节 SHA-256。

## 6. 失败语义

- 缺少 `BLOCKING` 项目事实：生成失败，不补零。
- 模型参数未落入显式版本包：生成失败。
- 工作簿发现公式错误：生成失败。
- 文件缺少 `SYNTHETIC_TEST_ONLY`：阶段门失败。
- 证据值与 ground truth 哈希不一致：阶段门失败。
- 期望数值哈希偏离当前全合同版本基线：阶段门失败。
