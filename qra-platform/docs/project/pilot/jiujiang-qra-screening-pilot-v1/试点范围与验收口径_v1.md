# 试点范围与验收口径 v1

## 1. 项目背景

平台已具备多格式上传、文档解析、OCR/模型提取框架、字段合同、证据和冲突治理、不可变快照、动态 QRA 和多格式报告能力。但当前两条原始资料转换任务被阻断，数据库中的实体、候选字段、候选证据和融合结果均为 0；现有快照也不是由本试点原始资料重新确认产生。第一版因此不扩展“任意资料识别”，而是固化一个可审计、可阻断、可验收的真实资料筛查范围。

## 2. 试点业务问题

本试点回答三个问题：

1. 用户应提供哪几类资料，每类资料能产生哪些现有标准字段；
2. 哪些字段足以运行证据条件化筛查链，哪些缺口只影响置信度，哪些缺口阻断试点或完整 QRA；
3. 从原始资料登记到 HTML/SVG 筛查报告，系统和人工分别留下哪些数据库与审计证据。

## 3. 资产与管线范围

- 资产类型：陆上埋地天然气输送管道；
- 管线：九江支线；
- `pipeline_id`：`GDBZYQ-JJ-1`；
- 第一版管段数：1；
- 管段边界：0.000～10.938 km；
- 管段长度：10.938 km；
- 范围外：芦溪支线、瑞昌支线、同表其他管线记录，以及无权威里程的现场照片变化点。

## 4. 权威管段划分来源

`SRC-JJ-001` 中 `GDBZYQ-JJ-1` 记录给出起点 JJ001（0+0）、终点 JJ041G（10+938）和 10,938 m 长度。现有九江映射对 `pipeline_id`/`segment_id` 进行行过滤，可以确定性排除其他支线。

用户已代表项目领导批准该来源和单段边界用于内部第一阶段测试，`segment_scope.status=CONFIRMED_FOR_INTERNAL_STAGE1_TEST`。该批准不等于正式工程签章或监管用途批准。如未来取得正式内部桩号或测绘坐标，应发布新试点版本、新映射/新快照；不得覆盖 v1 的单段证据。

## 5. 数据时间范围

现有台账能直接识别的部分数据范围为 2024-10-27 至 2026-04-25：前者是最新完整性评价摘要日期，后者是高后果区识别日期。采购文件和技术方案日期只属于项目治理时间，不代表工程观测日期。新增运行、CIPS、缺陷和人口资料必须逐项记录自己的起止日期，禁止用文件修改时间代替数据日期。

## 6. 文件类型白名单

| 文件类型 | 第一版用途 | 处理限制 |
|---|---|---|
| CSV/XLS/XLSX | 台账、运行、CIPS、缺陷维修、人口受体 | 优先确定性表格；公式、合并表头、单位和空值必须留证 |
| DOCX | 原生范围文件或结构化表格 | 自由文本候选必须人工复核；不得仅凭文字生成空间对象 |
| PDF | 原生或扫描证据 | 本阶段不调用外部 OCR；扫描件标记 `OCR_REQUIRED` |
| PNG/JPG/JPEG | 1～2 份扫描/现场佐证 | 无 GPS/里程不得映射为空间事实 |
| ZIP | 不在白名单 | 只能在受控区解包后逐文件登记，不能作为单一业务来源直接处理 |

任何未列类型均为 `UNSUPPORTED`。第一版不得宣传支持资料清单之外的“任意文件”。

## 7. 目标数据类别

1. 资产与权威管段台账；
2. 运行工况和输送介质；
3. 外腐蚀与 CIPS；
4. 检测、缺陷、维修和维护计划；
5. 人口、建筑和敏感受体；
6. 项目范围与治理文档；
7. 经 QRA 专家批准的标准、模型和参数库。

资料清单共 10 项：6 项本地可见、4 项待补。标准参考和技术方案只能支持定义与审批，不能自动成为真实工程事实。

## 8. 目标计算节点

| node_id | 业务含义 | 第一版角色 |
|---|---|---|
| `data_inventory` | 数据能力盘点 | 必须完成 |
| `indicator_coverage` | 工程指标覆盖率 | 必须完成 |
| `segment_geometry` | 管段几何与里程 | 必须完成；需 4 个逐段必需输入 |
| `adaptive_evidence_qra` | 自适应证据定量风险 | 必须完成；缺失证据边缘化并扩大不确定性带 |
| `risk_matrix` | 自适应风险结果展示矩阵 | 必须完成；只作展示，不替代接受性判定 |

HTML 仪表板和 SVG 图表是动态运行输出，不是另造的 `node_id`。

## 9. 筛查版与完整 QRA 版边界

| 维度 | 第一版筛查 | 完整 QRA 后续阶段 |
|---|---|---|
| 报告层级 | `EVIDENCE_CONDITIONED_SCREENING_ESTIMATE` | 取得完整资料和专家批准后另立范围 |
| 人员空间风险 | 不宣称可用 | 需要坐标、泄漏点、人口、天气、点火和伤害模型 |
| 失效频率 | 不作为第一版门槛 | 需要批准的分机理频率、孔径比例和修正模型 |
| AQ/T 3046 源项 | 不作为第一版门槛 | 需要压力、温度、壁厚、阀门、物性和批准参数 |
| 接受性结论 | 禁止 | 需要版本化风险准则和 QRA 专家签批 |
| 监管用途 | 禁止 | 必须另行履行法规、独立复核和正式报告流程 |

## 10. 角色和签批责任

| 角色 | 责任 | 第一版签批点 | 当前状态 |
|---|---|---|---|
| 业务负责人 | 确认管线、业务目的、资料权威性和使用范围 | 单段范围、报告用途、验收结论 | `VIRTUAL_STAGE1_TEST_BUSINESS_OWNER`；仅内部测试 |
| 数据负责人 | 控制源资料、保密权限、哈希和数据日期 | 文件清单、来源真实性、外发禁止 | `VIRTUAL_STAGE1_TEST_DATA_OWNER`；仅内部测试 |
| QRA 复核人 | 批准字段解释、参数、冲突决定和报告边界 | 管段范围、参数库、筛查声明 | `VIRTUAL_STAGE1_TEST_QRA_REVIEWER`；仅内部测试 |
| 合同维护者 | 维护 `field_id`、`target_path` 和兼容性 | 缺失业务字段的合同变更 | 待指定 |
| 平台实施人 | 执行受控转换、校验、快照和动态计算 | 技术运行记录与恢复记录 | 待指定 |

任何一人不得同时代替全部业务、数据和 QRA 签批。冲突字段不得按来源优先级自动确认。

上述三个虚拟角色是相互区分的测试身份，由用户于 2026-08-31 授权用于跑通第一阶段；正式发布前必须替换为可追责的真实任命和正式签批。

## 11. 数据外发规则

- `external_sharing_allowed=false`；
- 真实原始资料只允许位于 `workspace/pilots/jiujiang-qra-screening-pilot-v1/sources/`；
- 不得复制到 `tests/fixtures`、`resources`、`docs` 或其他 Git 跟踪目录；
- 受版本控制的清单只保存脱敏名、来源 ID、类型、大小、SHA-256、页/表数量、数据日期、业务分类、保密级别和不含正文的统计信息；
- 本阶段禁止真实云端 OCR 或大模型调用；
- 扫描资料待后续安全批准后只能按批准的本地/受控路线处理。

## 12. 通过、阻断和失败定义

### 通过

只有以下条件全部满足，机器报告才可为 `READY`：管线和权威管段已签批；资料白名单和报告层级明确；目标节点必需输入均有来源或显式 gap；开放 P0 为 0；源资料全部在批准目录且外发为 false；不需要编造工程事实；业务、数据、QRA 三方责任人已明确。本版已满足这些定义包条件，因此可进入内部实施。端到端运行成功是下一阶段门槛，还必须得到不可变快照、5 个目标节点完成、HTML/SVG 产物、结果层级正确和审计链完整。

### 阻断

定义或数据能够继续补正，且系统按规则停止在安全边界时记为 `BLOCKED`。典型情况包括 P0 未关闭、权威范围未签批、真实资料不在批准目录、关键冲突未复核、目标节点必需输入既无来源也无 gap。阻断不得通过填 0、默认值、测试 fixture 或降低报告层级约束来解除。

### 失败

配置引用未知 `field_id`/`node_id`/`source_id`、JSON/CSV 结构损坏、真实资料进入禁止目录、合成数据冒充真实数据、输出被误标为完整或正式 QRA、运行发生未隔离异常、哈希或审计证据不一致时记为 `FAILED`。失败后保留原任务和审计，修复配置或代码后创建新任务/新快照，不覆盖原证据。

## 13. 后续扩展范围

后续按独立版本逐步加入权威内部管段、中心线和阀门坐标、运行时序、CIPS、缺陷维修、人口受体、气象联合概率、失效频率库、物性与点火模型。只有完整人员域 QRA 的全部输入和专家批准齐备，才能考虑 `failure_frequency`、`leak_point_discretization`、`aqt3046_source_term`、`human_qra` 和正式准则校核；v1 成功标准不随扩展倒灌。
