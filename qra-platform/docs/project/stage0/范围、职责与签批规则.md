# 项目范围、职责与签批规则

## 1. 范围冻结

### 1.1 本期核心范围

- 资产：陆上埋地高压天然气输送管道；
- 试点：江西省天然气九江支线 GDBZYQ-JJ-1；
- 风险对象：人员生命风险；
- 结果：受控筛查、失效频率与场景、后果、IR、F-N、PLL、管段排序、数据缺口和审计；
- 工作链：源资料盘点、转换、人工复核、不可变快照、动态计算、报告和追溯；
- 当前目标成熟度：先达到 L2 真实数据试点，不承诺当前版本可签发正式工程报告。

### 1.2 本期排除项

- 财产、环境、供气可靠性及成本效益；
- 其他管线、站场、储罐、井和非天然气介质；
- 未经批准的生产参数、风险接受准则或正式结论；
- 企业级身份、HTTPS、备份和多租户上线能力；
- 从缺失数据、图片、OCR 或自由文本中自动猜测工程事实。

排除项如需纳入，必须新增需求和影响分析，经项目负责人批准后更新范围基线。

## 2. 角色与职责

当前仅开展内部功能验证，以下实名角色不作为 G0 阻断条件；进入工程模型验证、正式报告或生产发布前再完成指定和相互独立性要求。

| 角色 | 主要职责 | 阶段门责任 | 实名状态 |
|---|---|---|---|
| 项目负责人 | 范围、资源、计划、阶段门和最终决定 | 批准 G0～G6 | 待项目方指定 |
| 业务负责人 | 确认业务口径、现场解释、高风险结果合理性 | 会签 G0、G1、G2、G5 | 待项目方指定 |
| 数据负责人 | 确认授权、来源、边界、字段、冲突和黄金 JSON | 批准真实数据和 G1 | 待项目方指定 |
| 模型负责人 | 维护模型规格、参数来源、适用性和验证证据 | 组织 G3、G4 | 待项目方指定 |
| 模型独立复核人 | 独立复核公式、参数、外部基准和结论 | 会签 G3、G4、G5 | 待项目方指定；不得由主要开发者兼任 |
| 平台开发负责人 | 代码、测试、转换、计算、缺陷和发布记录 | 提供各门技术证据 | 待项目方指定 |
| 验收人 | 对交付物、证据和遗留项作接受决定 | 批准 M1～M6 | 待项目方指定 |
| 计划维护人 | 维护计划、登记册、会议与签批记录 | 维护阶段门状态 | 项目组，实名待补 |

上述角色可以一人兼任，但数据确认、模型独立复核和最终验收不得全部由同一名主要开发者承担。

## 3. RACI 最小矩阵

| 工作 | 项目负责人 | 业务负责人 | 数据负责人 | 模型负责人/复核人 | 平台开发 | 验收人 |
|---|---|---|---|---|---|---|
| 范围和试点 | A | C | C | C | I | C |
| 数据授权和目录 | I | C | A/R | I | C | I |
| 专用映射和转换 | I | C | A | C | R | I |
| 黄金 JSON | I | C | A/R | C | C | I |
| 模型和参数 | I | C | C | A/R | R | I |
| 外部验证 | I | C | I | A/R | C | C |
| 阶段验收 | A | C | C | C | C | R |

`A` 为最终负责，`R` 为执行，`C` 为会商，`I` 为知会。

## 4. 后续工程签批方式

默认使用“版本化 Markdown 记录 + Git 提交哈希”电子签批：

1. 每位签批人填写姓名、单位、角色、结论、日期和意见；
2. 计划维护人提交签批后的文件，记录提交哈希；
3. 若客户制度要求手写或合规电子签名，则从同一版本导出 PDF 签署，并在本记录中登记 PDF 文件名和 SHA-256；
4. 进入需正式签批的工程阶段后，任一签批人提出实质异议时，对应阶段门维持 `HOLD`，不得以口头意见替代书面结论。
