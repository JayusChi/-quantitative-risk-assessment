# 第三阶段实施说明：文档解析、OCR 与版面识别

## 1. 文档定位

本文是《第一部分项目计划书》的第三阶段可执行开发规格。第三阶段把第二阶段已安全登记的文件转换为统一、忠实、带位置证据的机器可读内容。解析层只回答“原文件中有什么、在哪里”，不决定哪个内容是最终 QRA 字段值。

## 2. 阶段目标与出口

支持 CSV、XLS、XLSX、DOCX、文本 PDF、混合 PDF、扫描 PDF、PNG 和 JPG/JPEG。每个文本块、表格单元格和图像区域都能反查源文件位置；无法可靠读取的内容生成结构化问题，不以空字符串或猜测结果冒充成功。

阶段出口：全部支持格式可输出统一 `ParsedDocument`；关键表格值能定位到工作表/单元格或页码/坐标；扫描资料通过配置的 OCR 提供方形成带置信度结果；低质量和异常版面被明确标记并进入后续复核。

## 3. 当前基线与复用要求

现有读取能力：

- `src/qra_converter/readers/tabular.py`：CSV、XLS、XLSX 读取为 `RawTable`；
- `src/qra_converter/readers/documents.py`：DOCX 原生表格和自由文本辅助提取；
- `src/qra_converter/readers/pdf.py`：`pdfplumber` 表格或 `pypdf` 文本辅助提取；
- `src/qra_converter/contracts.py`：`SourceReference`、`RawRow`、`RawTable`、`FieldLineage`；
- `src/qra_converter/service.py`：按受支持后缀发现文件并统一调用读取器。

必须保留 CSV/XLS/XLSX 的现有确定性行为和测试。新增统一文档模型后，通过兼容适配器向现有映射器输出 `RawTable`，直到第四阶段完成候选字段流水线，不一次性删除旧合同。

## 4. 范围边界

本阶段包括：

- 文件技术路由、原生解析、图片预处理、OCR 和表格结构重建；
- 文档块、表格、单元格、图片和元数据的统一输出；
- 页码、坐标、工作表、行列和 DOCX 结构位置；
- 清晰度、文本覆盖、OCR 置信度和版面异常问题；
- 解析结果版本化、缓存和回归测试。

本阶段不包括：

- 将“工作压力”映射为 `pipeline.operating_pressure`；
- 使用大模型判断资料主题、实体或业务关系；
- 多来源合并、冲突裁决和计算快照；
- 执行 DOCX 宏、Excel 公式、PDF JavaScript 或嵌入附件；
- 为 DOCX 伪造无法可靠获得的页码。

## 6. 统一解析合同

### 6.1 `ParsedDocument`

在 `parsing/contracts.py` 定义冻结数据类或等价不可变对象：

```text
ParsedDocument
├─ document_id
├─ source: SourceReference
├─ media_type
├─ document_kind
├─ parser_id / parser_version
├─ page_count
├─ pages[]
├─ tables[]
├─ images[]
├─ metadata
├─ issues[]
└─ parse_sha256
```

`parse_sha256` 对不包含运行时间的规范化解析 JSON 计算。相同源文件、解析器版本、OCR 提供方版本和参数必须产生相同哈希；外部 OCR 非确定时仍保存原始响应哈希和调用 ID，不能声称字节级确定性。

### 6.2 文本块

`TextBlock` 至少包含：

- `block_id`、`page_number` 或 DOCX 结构位置；
- `text`、`reading_order`、`block_type`；
- `bbox`、`coordinate_space`、页面宽高；
- `extraction_method`、`confidence`、`language`；
- `style_hint`：标题级别、粗体等可用但非权威的格式线索；
- `source_fragment_sha256`。

文本必须保留原文；去空白、全半角和 OCR 易错字符修正写入单独的 `normalized_text` 或后续标准化结果，不覆盖原文。

### 6.3 表格与单元格

`ParsedTable` 包含表格 ID、页/工作表、标题候选、边界框、行列数、跨页关系和单元格。`ParsedCell` 至少包含：

- 0 基内部 `row_index/column_index` 和用户显示用地址；
- `row_span/column_span`；
- `raw_value`、`display_text`、`value_type`；
- 公式文本与缓存值分开保存；
- 工作表单元格引用或页面边界框；
- 提取方法和置信度。

合并单元格不得把值复制成多个“原始值”。保留主单元格及跨度；兼容 `RawTable` 时可以生成展示矩阵，但必须标记哪些单元格是合并展开值。

### 6.4 图片与页面

`ImageRegion` 保存图片 ID、来源部件/页码、bbox、像素尺寸、内容哈希和可选 OCR 块。解析产物可以保存受控预览图，但不得把 Base64 大图嵌入数据库 JSON。

PDF/图片 bbox 统一使用左上角为原点的页面/像素坐标，并保存宽高。适配 `pdfplumber` 等不同坐标系时在 `geometry.py` 统一转换并测试。

## 7. 文件路由与流水线

固定流水线：

```text
READY_FOR_PARSE 源文件
  → 按第二阶段 detected_media_type 选择读取器
  → 结构/密码/页数再次校验
  → 原生内容解析
  → 按页质量检测和 OCR 路由
  → 版面与表格结构统一
  → 证据坐标校验
  → 解析质量报告
  → 固化 ParsedDocument 与预览资源
```

读取器注册使用明确的 media type 和能力声明，不再只按后缀抢占。一个文件只能有一个主读取器；PDF 内可按页选择原生文本或 OCR。

每个阶段捕获可预期的库异常并转换为 `PARSE.*` 问题。未知编程错误使该文件 `PARSE_FAILED`，由任务策略决定是否阻断整个任务。

## 8. 各格式实现要求

### 8.1 CSV

- 保留 UTF-8-SIG、GB18030 和现有分隔符探测；
- 记录编码、分隔符、换行类型和实际物理行范围；
- 正确处理引号内换行，`source_location` 使用记录起止物理行；
- 不自动把长编号、桩号或前导零字符串转数值；
- 空值与空字符串分开表示；
- 无法确定方言时返回警告和使用的回退规则。

### 8.2 XLS/XLSX

- 每个工作表形成页面等价结构；
- 保存隐藏工作表、隐藏行列、合并单元格、冻结窗格和表格范围等元数据；
- 读取公式文本和缓存值；没有缓存值时不得执行公式；
- 日期保留原 Excel 值、显示值和解析日期；
- 外部链接、宏和嵌入对象不执行，只记录存在性问题；
- `read_only=True/data_only=True` 不足以同时获得公式时，可受控双开工作簿并以单元格地址合并，测试大文件内存上限。

### 8.3 DOCX

- 提取标题、段落、原生表格、页眉页脚引用、图片和题注关系；
- 位置用 `document.xml` 部件、段落序号、表格/行/列表示；
- Word 页码依赖字体和版式，未经过确定性渲染时 `page_number=null`；
- 图片 OCR 结果挂在图片区域，不混入相邻段落原文；
- 修订、批注、文本框和嵌入对象至少产生“存在但未完整支持”的问题；
- 禁止处理 `.docm`，第二阶段应已隔离。

### 8.4 PDF

按页计算原生文本字符数、有效字符比例、图像覆盖率和表格可提取性：

- `TEXT_NATIVE`：原生文字充足，优先原生文本和表格；
- `MIXED`：原生文本与扫描区域共存，只 OCR 缺失区域或页面；
- `SCAN`：无有效文字或整页图像，走 OCR；
- `UNREADABLE`：加密、损坏或页尺寸异常，结构化失败。

原生提取和 OCR 对同一区域都存在时，不直接拼接。按坐标重叠和置信度选择显示层，并保留两个提取候选供质量检查。PDF 页码严格从 1 开始。

### 8.5 PNG/JPG/JPEG

- 使用图像库验证、读取 EXIF 方向并转正；
- 原始图像只读，预处理生成派生图和参数记录；
- 检测分辨率、模糊、过曝、欠曝、倾斜和截边；
- 可实施自动旋转、灰度、对比度、去噪、透视校正，但每一步保存版本和参数；
- 原图坐标和预处理图坐标间必须有可逆变换矩阵，最终证据回写原图坐标；
- 超大图使用像素和内存上限，防止解压炸弹。

## 9. OCR 端口与提供方

### 9.1 端口

`ocr/ports.py` 定义：

```text
OcrProvider.recognize(request) -> OcrResponse

OcrRequest:
  image_bytes/image_ref, width, height, languages,
  detect_tables, request_id, timeout_seconds

OcrResponse:
  provider_id, model_version, text_blocks, tables,
  warnings, raw_response_sha256, provider_request_id
```

模型密钥和端点只从部署配置读取，不进入任务 JSON、日志或快照。提供方失败必须区分超时、限流、认证、不可读和输出合同错误。

### 9.2 路由和降级

- 原生解析优先，不能对所有 PDF 无条件 OCR；
- OCR 只接收受控图像字节，不接收原始文件系统路径；
- 超时可按配置重试，默认最多 2 次，指数退避；
- 同一内容哈希、模型版本和参数可复用缓存；
- 未配置 OCR 时使用 `DisabledOcrProvider` 返回 `PARSE.OCR_PROVIDER_NOT_CONFIGURED`，不得返回伪文本；
- 自动化测试使用 `fixture_provider` 返回由夹具标注的确定结果；真实扫描件验收使用实际配置提供方并记录版本。

## 10. 版面和表格重建

表格重建顺序：

1. 使用原生表格结构；
2. 使用 OCR 提供方返回的表格网格；
3. 在网格缺失时按文本块坐标聚类生成“推测表格”，置信度不得高于配置上限；
4. 检测跨页表头重复、列边界一致和表题连续性，生成跨页关系候选；
5. 多行表头保留原始行，第四阶段再解释语义；
6. 表格脚注与数据行分开，无法区分时生成 `PARSE.TABLE_FOOTNOTE_AMBIGUOUS`。

跨页表格只建立 `continuation_of` 关系，不在解析层删除重复表头或合并业务记录。任何推测关系都必须有置信度和规则版本。

## 11. 解析质量与问题码

至少实现：

- `PARSE.DOCUMENT_CORRUPT`；
- `PARSE.ENCRYPTED_UNSUPPORTED`；
- `PARSE.NO_CONTENT`；
- `PARSE.OCR_REQUIRED`；
- `PARSE.OCR_PROVIDER_NOT_CONFIGURED`；
- `PARSE.OCR_TIMEOUT`；
- `PARSE.LOW_TEXT_CONFIDENCE`；
- `PARSE.IMAGE_BLURRY/OVEREXPOSED/UNDEREXPOSED`；
- `PARSE.TABLE_STRUCTURE_UNCERTAIN`；
- `PARSE.MERGED_CELL_EXPANDED`；
- `PARSE.FORMULA_VALUE_MISSING`；
- `PARSE.UNSUPPORTED_EMBEDDED_OBJECT`；
- `PARSE.LOCATION_INVALID`。

质量报告按文件、页、表格统计：原生字符数、OCR 字符数、平均/最低置信度、表格数、低置信块数、无内容页数和处理耗时。统计只用于路由和复核，不作为业务事实。

## 12. 产物与持久化

每个文件至少产生：

```text
parsed/<source_id>/
├─ parsed_document.json
├─ quality_report.json
├─ preview_manifest.json
└─ previews/...
```

产物记录源文件哈希、解析器版本、OCR 提供方/模型版本、预处理版本和合同版本。大图、页面预览和 OCR 原始响应不直接嵌入 `conversion_job` JSON；数据库保存受控资源引用和哈希。

解析缓存键：`source_sha256 + parser_id/version + ocr_provider/model + preprocessing_profile + contract_version`。缓存命中仍建立当前任务与产物的来源关系。

## 13. 代码任务拆分

### 13.1 任务 A：统一模型和兼容层

1. 定义解析数据类和 JSON 序列化；
2. 为现有 `RawTable` 编写 `ParsedDocument → RawTable` 兼容适配器；
3. 保证原 CSV/XLS/XLSX 黄金测试不变；
4. 实现 bbox 坐标转换和校验；
5. 实现规范化解析哈希。

### 13.2 任务 B：确定性读取器

1. 拆分并增强 CSV/Excel；
2. 增强 DOCX 段落、表格和图片关系；
3. 实现 PDF 按页路由；
4. 实现图像读取和质量检测；
5. 注册表改为按检测媒体类型路由。

### 13.3 任务 C：OCR 与预处理

1. 定义提供方端口、超时、重试和响应 Schema；
2. 实现禁用提供方和测试夹具提供方；
3. 实现至少一个部署可用的真实提供方适配器或明确的可插拔配置；
4. 实现图像方向、清晰度和基础预处理；
5. 实现坐标回写和缓存。

### 13.4 任务 D：持久化和任务进度

1. 每个源文件独立更新 `PARSED/PARSE_FAILED`；
2. 任务进度按文件和页计算，不能只写固定 45/90；
3. 取消标记在每页/OCR 调用前检查；
4. 保存解析产物引用和质量摘要；
5. 原始文件不因解析成功被删除或改写。

## 14. 黄金资料与测试

创建完全合成夹具：

- CSV：多编码、引号换行、前导零、不同分隔符；
- XLS/XLSX：多工作表、公式、合并表头、隐藏行列、日期、空单元格；
- DOCX：标题、段落、原生表格、图片、文本框/批注存在性；
- PDF：纯文本、原生表格、文本加扫描混合、纯扫描、旋转页、跨页表格；
- 图片：清晰、倾斜、模糊、反光、低分辨率、EXIF 旋转和裁切；
- 异常：损坏、加密、空内容、超大尺寸。

每个夹具配 `expected.json`，标注预期文本、表格结构、位置和问题。对 OCR 结果使用容差和归一化比较，不只比较整段字符串。

单元测试必须覆盖每个读取器、bbox、哈希、缓存和错误映射。集成测试必须覆盖从 `READY_FOR_PARSE` 文件到解析产物固化的完整链路。真实 OCR 冒烟测试单独标记，需要配置时可跳过，但阶段验收不能只用夹具提供方代替真实扫描件。

## 15. 验收指标

- 结构化 CSV/XLS/XLSX 受支持单元格忠实读取率不低于 99.9%；
- 原生表格的工作表、行列证据绑定率 100%；
- PDF/图片 OCR 块的页码/坐标绑定率 100%；
- 低于阈值的 OCR 块 100% 标记，不进入“可靠原文”集合；
- 预设旋转、模糊、空页和表格结构异常全部检出；
- DOCX 无可靠分页时不输出伪页码；
- 解析失败返回问题码，不生成假内容；
- 相同确定性输入和版本产生相同解析哈希；
- 旧转换器结构化表格回归保持通过。

## 17. 向第四阶段移交

移交 `ParsedDocument`、质量报告、预览资源、解析/OCR 版本和所有问题。第四阶段只能引用解析块和证据 ID，不得把模型生成文本写回解析原文，也不得丢失坐标或覆盖低置信度标记。
